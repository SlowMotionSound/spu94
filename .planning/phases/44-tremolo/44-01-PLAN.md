  <action>
    In PluginProcessor.h, add these atomic state variables in the same section as the existing VCA ramp controls:
    - std::atomic bool tremoloEnabled (default false)
    - std::atomic float tremoloSpeedHz (default 5.0f)
    - std::atomic float tremoloDepth (default 1.0f, range 0.0-1.0)
    - std::atomic int tremoloCurve (default 0, 0=linear 1=exponential)
    - std::atomic float tremoloRatio (default 1.0f, range 0.5-4.0)
    Add getter references for each following the existing pattern (getRampDirection etc).

    In PluginProcessor.cpp, create a hzToShift helper function in the anonymous namespace (alongside the existing speedToShift). The math: a full cycle at 44100 Hz sample rate with the counter-accumulate system has a half-cycle duration of 0x7FFF ticks divided by the step-per-tick. Step-per-tick for shift S, step=3 is (7 - step) shifted left by (11-S) when S less than 11, or shifted right by (S-11) otherwise. Build a lookup table mapping shift values 2 through 25 to their resulting Hz (full cycle = 2 half-cycles). The function finds the nearest entry.

    Concrete Hz-to-shift derivation: The counter-accumulate mechanism increments the counter by (0x8000 >> max(0, shift-11)) per tick. When counter overflows 0x8000, a step is applied. The step magnitude for linear increase is (7 - step_param). So ticks-per-level-change = 0x8000 / (0x8000 >> max(0, shift-11)) = 1 << max(0, shift-11). For step=3 (step magnitude = 4), the level changes by 4 each time. A half-cycle from 0 to 0x7FFF takes 0x7FFF / 4 = 8191 level changes. At ticks-per-change rate, total ticks for half-cycle = 8191 * (1 << max(0, shift-11)). Full cycle Hz = 44100 / (2 * half_cycle_ticks).

    Build kTremoloHzTable as an array of structs (shift, step, hz_value) covering shift 2..25, step=3 (maximum step magnitude gives finest granularity at each shift). The function hzToShift(float hz) iterates the table and returns the entry with minimum absolute log-ratio distance.

    In processBlock, AFTER the existing VCA ramp activation block (around line 680), add tremolo activation logic:
    - Read tremoloEnabled. If true and sweep is NOT already active in retrigger mode (check voices[0].sweep_l.retrigger_enable and voices[0].sweep_l.active):
      - Convert tremoloSpeedHz to shift/step via hzToShift
      - For the L channel: call spu94_voice_mixer_set_sweep_l with mode=tremoloCurve, direction=1 (start decreasing from current vol), phase=0, shift from hzToShift, step from hzToShift, retrigger_enable=1
      - For the R channel: apply ratio -- if ratio is 1.0 use same shift; if ratio > 1.0 use shift+floor(log2(ratio)) clamped 0..31; if ratio < 1.0 use shift-floor(log2(1/ratio)) clamped 0..31
      - Same call pattern for R: spu94_voice_mixer_set_sweep_r with retrigger_enable=1
    - If tremoloEnabled changes to false (was previously active), deactivate sweep on both channels: set voices[0].sweep_l.active=0 and voices[0].sweep_r.active=0

    For depth scaling: read the sweep level each tick and apply depth before writing back to vol. The sweep tick already writes sweep.level into vol_l/vol_r (in spu94_voice_tick STEP 0). After the voice tick, if tremolo is active, read the base volume (0x7FFF for full positive) and compute: effective_vol = base_vol - depth * (base_vol - sweep_level). Actually simpler: since sweep oscillates between 0 and 0x7FFF, and the sweep level IS the volume, depth means "what fraction of the modulation range actually applies." At depth=1.0, vol ranges 0..0x7FFF. At depth=0.5, vol ranges 0x3FFF..0x7FFF. Implement this in processBlock after sweep tick by adjusting vol: voices[0].vol_l = 0x7FFF - (int16_t)((float)(0x7FFF - voices[0].sweep_l.level) * depth). Same for R. This runs every processBlock call (control rate is fine for tremolo).

    Add a bool member tremoloWasActive (non-atomic, audio-thread-only) initialized to false, to detect enable/disable transitions.

    When tremoloSpeedHz or tremoloCurve or tremoloRatio change while tremolo is active, re-call set_sweep_l/r to update. Detect via comparing current values to cached copies (audio-thread-local floats lastTremoloHz, lastTremoloCurve, lastTremoloRatio).

    IMPORTANT: Tremolo and manual VCA ramp are mutually exclusive. When tremolo is enabled, the rampArm exchange should be suppressed (skip the rampArm block). Add a guard: if (tremoloEnabled.load) skip the rampArm check.
