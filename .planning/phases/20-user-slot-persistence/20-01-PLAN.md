# Phase 20 Plan 01: User Slot Persistence

Persist filled user slots inside the existing INI-style `.spu94` preset format. Empty slots are omitted entirely so legacy presets stay byte-identical to their pre-feature serializations, and pre-feature files load cleanly with all slots empty.

## Rationale

User slots are useless if they don't survive a relaunch. Persistence rides on top of the v1.4 preset format (registers + mixer + DAC sections) by adding a new section type. Backward compatibility is non-negotiable: pre-feature presets must load without modification and post-feature presets without filled slots must serialize identically to pre-feature ones.

## Design

- New section header: `[user_slot N]` (N = 0..7)
- Section body: same `key=hex_value` shape as the existing `[registers]` section, listing all 35 register fields
- Saver omits sections for unfilled slots — file shape with all slots empty == pre-feature shape exactly
- Loader's section dispatch grows a `SECTION_USER_SLOT` case; the scratch buffer is committed via `spu94_interp_set_user_slot` at section boundary
- Buffer size bumped 4096 → 8192 to fit 8 filled slots (~5900 bytes worst case)

## Test Coverage

| Test | What |
|------|------|
| Round-trip with 3 filled slots | Save preset, load it, verify all 8 slots' filled state matches and filled slots have byte-identical registers |
| Back-compat (pre-feature file) | Load a preset saved before this feature existed — assert all 8 slots are empty, no parse errors |
