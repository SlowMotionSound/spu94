<objective>
Add auto-reversing retrigger capability to the existing spu94_sweep_t state machine, so a sweep can continuously oscillate between its clamping boundaries instead of stopping at the limit.

Purpose: This is the foundation for all downstream v1.10.0 modulation effects (tremolo, auto-pan, AM synthesis). Without retrigger, every effect would need host-layer polling, adding latency and complexity. With retrigger in the C core, oscillation is sample-accurate and RT-safe.

Output: Modified spu94_sweep.h with retrigger_enable field, modified spu94_sweep.c with auto-reverse logic in spu94_sweep_tick, and expanded test_sweep.c with retrigger-specific tests.
</objective>

typedef struct {
    int16_t  level;       /* current sweep level (IS the volume) */
    uint32_t counter;     /* counter-accumulate state */
    uint8_t  shift;       /* 0..31: controls counter increment rate */
    uint8_t  step;        /* 0..3: controls step magnitude */

    uint8_t  direction;   /* 0 = increase, 1 = decrease */
    uint8_t  phase;       /* 0 = positive, 1 = negative (inverts step sign) */
    uint8_t  active;      /* 0 = inactive, 1 = sweeping */
} spu94_sweep_t;

void spu94_sweep_init(spu94_sweep_t *sw);
void spu94_sweep_tick(spu94_sweep_t *sw);
void spu94_sweep_configure(spu94_sweep_t *sw,

                           uint8_t shift, uint8_t step);

Clamping boundaries (from spu94_sweep.c):
- phase=0, increase: clamp at +0x7FFF
- phase=0, decrease: clamp at 0x0000
- phase=1, increase: clamp at -0x7FFF
- phase=1, decrease: clamp at 0x0000
- Exception: phase bit ignored when direction=decrease AND mode=exponential
