<objective>
Teach the sampler engine an active-voice count (1-24, default 24) and bound the
existing round-robin allocator to it, so played notes allocate only among the
active voices and overflow reuses the least-recently-allocated voice. Prove all
four success criteria with a new headless CTest that observes allocation directly
via the voice mixer's synchronously-set pending_kon / pending_koff bitmasks.

Purpose: This is the foundation phase of v1.12.0 Voice Count. Phases 61 (controls),
62 (GUI selector), and 63 (persistence) all build on the engine knowing a count.
The feature itself is small and localized (60-RESEARCH.md, HIGH confidence,
line-cited against HEAD): add a clamped atomic + setter and change two hardcoded
24 literals in allocateVoice to use the count. The real deliverable is the test,
because allocateVoice has had ZERO coverage since Phase 31 and there is no existing
regression guard for the default-24 path.

Output: A count-aware allocator in src/plugin/PluginProcessor.{h,cpp}, a test seam,
and tests/plugin/test_voice_alloc.cpp wired into CTest with five passing cases
(four behavioral + one default-24 regression guard).
</objective>
