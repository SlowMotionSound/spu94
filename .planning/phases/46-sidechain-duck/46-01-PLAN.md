<objective>
Implement sidechain duck detection and sweep configuration in processBlock so that
one voice's KON event triggers a volume drop on another voice, with automatic
exponential recovery after the drop completes.

Purpose: This gives the sampler rhythmic pumping (sidechain compression feel) using
only the existing VCA sweep hardware -- no new DSP, just event-triggered one-shot
ramps configured from the host layer.

Output: Per-voice duck source/release/depth atomics, KON detection logic, duck
state machine (idle -> ducking -> recovering -> idle), integration test.
</objective>

     - enum DuckPhase { DUCK_IDLE, DUCK_DECREASING, DUCK_RECOVERING }

  IMPLEMENTATION (PluginProcessor.cpp):

  4. Duck attack speed: hardcode shift=10 (0.05s -- fast exponential slam). This is the "attack" of the compressor. Not user-configurable because sidechain compression always has fast attack.

  5. KON snapshot: BEFORE the existing `spu94_voice_mixer_tick` call in the per-sample loop, snapshot `mx->pending_kon` into a local uint32_t `kon_snapshot`. The mixer_tick clears pending_kon, so we must read it first. This snapshot tells us which voices just triggered KON this tick.

  6. Duck trigger logic: AFTER the mixer_tick call (so the KON voice is now actually sounding), iterate voices 0-23. For each voice v with duckState[v] == DUCK_IDLE:
     - Read duckSource[v]. If -1, skip.
     - Check if kon_snapshot has bit (1u << duckSource[v]) set.
     - If yes: duck triggers on voice v.
       a. Store current vol_l/vol_r as duckOrigLevel_l[v] / duckOrigLevel_r[v]
       b. Configure exponential decrease: spu94_voice_mixer_set_sweep_l(mx, v, 1 (exp), 1 (decrease), 0 (phase), 10 (shift=fast), 0 (step), 0 (retrigger=one-shot))
       c. Same for sweep_r.
       d. Set duckState[v] = DUCK_DECREASING.

  7. Depth scaling: After duck sweep is configured but before any other processing, apply depth. When depth < 1.0, the target level is not 0 but (1.0 - depth) * originalLevel. Implement this by monitoring sweep_l.level each tick: when level reaches the floor (0 or depth-scaled floor), deactivate sweep and set duckState to DUCK_RECOVERING.

     Concrete depth mechanism: After the duck decrease sweep is configured, DON'T let it run all the way to 0. Each processBlock iteration, for any voice in DUCK_DECREASING state:
     - Compute floor_l = (int16_t)((1.0f - depth) * duckOrigLevel_l[v])
     - If mx->voices[v].sweep_l.level <= floor_l OR mx->voices[v].sweep_l.active == 0:
       - Set mx->voices[v].sweep_l.active = 0
       - Set mx->voices[v].vol_l = floor_l (clamp at the depth-scaled floor)
       - Same for R channel
       - Transition: duckState[v] = DUCK_RECOVERING
       - Configure increase sweep from floor back to original level:
         spu94_voice_mixer_set_sweep_l(mx, v, 1 (exp), 0 (increase), 0 (phase), releaseShift, 0 (step), 0 (retrigger=one-shot))
         where releaseShift = speedToShift(duckRelease[v]) using the existing helper.
         Set sweep_l.level = floor_l before activate (the set_sweep API already initializes level from current vol_l).

  8. Recovery completion: For any voice in DUCK_RECOVERING state:
     - If mx->voices[v].sweep_l.active == 0 AND mx->voices[v].sweep_r.active == 0:
       - Restore vol_l = duckOrigLevel_l[v], vol_r = duckOrigLevel_r[v] (ensure we land exactly at original)
       - Set duckState[v] = DUCK_IDLE

  9. Mutual exclusion with tremolo/auto-pan/VCA ramp: The existing tremolo and auto-pan only operate on voice 0. Duck operates on voices 0-23. Add a guard: if duckState[v] != DUCK_IDLE for voice 0, skip the tremolo/auto-pan/VCA ramp activation for voice 0. Conversely, if tremoloEnabled or autoPanEnabled for voice 0, duck cannot trigger on voice 0 (duck source for voice 0 is effectively disabled while tremolo/pan are active).

     For voices 1-23, duck is the only sweep consumer (tremolo/auto-pan only touch voice 0 currently), so no additional exclusion needed.

  10. Placement in processBlock: The duck logic goes inside the existing standalone per-sample loop, positioned AFTER the tremolo/auto-pan block (around line 990) but BEFORE the mixer_tick call... Actually, reconsider: the KON snapshot must happen at the per-sample level since mixer_tick runs per-sample. Structure:
      - For each sample in the block:
        - ... existing pre-tick logic ...
        - kon_snapshot = mx->pending_kon (read BEFORE tick)
        - spu94_voice_mixer_tick(...)  (existing call)
        - Duck trigger check (using kon_snapshot)

      The sweep configuration calls (set_sweep_l/r) take effect on the NEXT tick, which is fine -- one sample of latency is inaudible.

  IMPORTANT: The processBlock currently calls set_sweep_l/r at the block level (once per buffer) for tremolo/auto-pan. Duck must also detect and configure at the per-sample level because KON events are per-sample (mixer_tick runs once per sample). Find the per-sample loop in processBlock and add the duck logic there.
