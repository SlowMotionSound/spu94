## Decisions Made This Session

- **CLI uses `spu94_reset(state)` after `spu94_init`** — Per the library's documented D-14 contract, `spu94_init` does NOT zero the caller-owned work buffer; only `spu94_reset` does. The CLI was trusting `spu94_init` alone and getting heap residue in the reverb's delay lines. One-line fix in `src/cli/main.c`. Library API untouched.
- **Q15 semantics pinned for `spu94_reverb_input_scale`** — Switched from raw int16×int16 widening multiply to `q15_mul_truncate_with_err`. Every other reverb multiply already used Q15 per psx-spx ("multiplication results are divided by 0x8000"). The input_scale stage was the only holdout.
- **Tail-lockup investigation deferred to Phase 7** — Not blocking any user-visible deliverable. Needs witness harness that doesn't exist yet.
