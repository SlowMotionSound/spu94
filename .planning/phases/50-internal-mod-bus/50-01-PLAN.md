<objective>
Internal mod bus C core implementation and host-layer wiring

Purpose: Make each voice a self-contained sound design instrument by routing the global noise generator output as a modulation source to three destinations (pitch, volume, pan) per voice. On real PS1 hardware this requires dedicating a separate NON voice + PMON chain; the internal mod bus internalizes that routing so a single voice can produce noise-modulated textures without consuming a second voice slot. This runs at sample rate inside the C core voice tick for zero-latency modulation.

Output: Three per-voice depth fields in the voice struct, noise modulation injection in spu94_voice_tick, mixer setter API, atomic GUI-to-audio bridge in PluginProcessor, and unit tests proving all three destinations work independently and simultaneously.
</objective>

In spu94_voice.c:
3. In spu94_voice_tick, insert mod bus processing between STEP 0 (sweep) and STEP 1 (decode). The injection point is AFTER sweep has updated vol_l/vol_r but BEFORE any decode or interpolation. The modulation targets:

   a. PITCH modulation (MOD-01): After Step 4's pitch advance calculation, the effective_pitch should incorporate noise. Instead, modulate the pitch register temporarily (same save/restore pattern as PMON in the mixer tick). Actually, since spu94_voice_tick receives noise_level already, the simplest approach is to modulate the pitch used in Step 4 inside the voice tick itself:
      - Between STEP 2.75 (outx store) and STEP 4 (pitch counter advance), compute:
        int32_t pitch_mod = ((int32_t)noise_level * (int32_t)v->noise_mod_pitch_depth) >> 15;
        int32_t mod_pitch = (int32_t)v->pitch + pitch_mod;
        Clamp mod_pitch to 0..0x4000 (same range as PMON allows).
        Use mod_pitch instead of v->pitch for the Step 4 counter advance.
      - This means saving the base pitch and using the modulated value locally (do NOT write back to v->pitch -- same pattern as PMON).

   b. VOLUME modulation (MOD-02): Before Step 3 applies volume, compute:
        int32_t vol_mod = ((int32_t)noise_level * (int32_t)v->noise_mod_vol_depth) >> 15;
        int32_t mod_vol_l = (int32_t)v->vol_l + vol_mod;
        int32_t mod_vol_r = (int32_t)v->vol_r + vol_mod;
        Clamp both to -0x4000..+0x3FFF.
        Use mod_vol_l and mod_vol_r in the Step 3 q15_mul_truncate calls instead of v->vol_l/vol_r.
      - Do NOT write back to v->vol_l/vol_r (modulation is per-tick, not persistent).

   c. PAN modulation (MOD-03): Before Step 3, compute:
        int32_t pan_mod = ((int32_t)noise_level * (int32_t)v->noise_mod_pan_depth) >> 15;
        Add pan_mod to mod_vol_l, subtract pan_mod from mod_vol_r (or start from the vol-modulated values if vol mod is also active).
        Re-clamp both to -0x4000..+0x3FFF.
      - This creates stereo jitter: when noise is positive, L gets louder and R gets quieter; when negative, the reverse.

   Implementation order within the tick: compute mod_vol_l/mod_vol_r from vol_l/vol_r + vol_mod + pan_mod, then use them for Step 3. Compute mod_pitch from pitch + pitch_mod, then use it for Step 4. All arithmetic uses int32_t intermediates to prevent overflow before clamp.

   Key constraints:
   - When all three depth fields are 0, the code path must produce BIT-IDENTICAL output (the multiplies yield 0, offsets are 0). Use early-out checks: if all three depths are 0, skip the mod bus block entirely.
   - Do NOT modify v->vol_l, v->vol_r, or v->pitch -- modulation is ephemeral per-tick.
   - noise_level is already passed into spu94_voice_tick as a parameter (it comes from the global noise generator that ticks once before the voice loop in mixer_tick). This is the correct value to use regardless of whether the voice is NON-enabled or not -- NON substitutes noise for the AUDIO OUTPUT, but the mod bus uses noise as a CONTROL SIGNAL even on normal voices.

4. Implement spu94_voice_mixer_set_mod_bus in spu94_voice.c (after the existing set_sweep functions):
   - Validate voice_idx 0..23, return SPU94_INVALID_ARG if out of range.
   - Set m->voices[voice_idx].noise_mod_pitch_depth = pitch_depth
   - Set m->voices[voice_idx].noise_mod_vol_depth = vol_depth
   - Set m->voices[voice_idx].noise_mod_pan_depth = pan_depth
   - Return SPU94_OK.

5. In spu94_voice_init, the memset already zeros all fields (including the new depth fields), which means depth=0 = no modulation by default. No extra init code needed.
