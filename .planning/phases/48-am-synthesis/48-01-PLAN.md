  - Add audio-thread-only state: amWasActive{false}, lastAmHz{-1.0f}, lastAmCurve{-1}.

  In PluginProcessor.cpp (anonymous namespace, after existing kTremoloHzTable):
  - Create kAmHzTable covering shifts 0-8 with steps 0-3. Use the same counter-accumulate math as the tremolo table but for these lower shifts. At shift 0, the counter increment is 0x8000 >> max(0, 0-11) = 0x8000 (fires every tick). At shift 8, counter increment is 0x8000 >> max(0, 8-11) = 0x8000 (fires every tick, same as shifts 0-10 all fire every tick since max(0, shift-11) is 0 for shift <= 11). Step magnitude for shift <= 11: (7-step) << (11-shift). So for shift=0 step=0: magnitude = 7 << 11 = 14336; half_cycle = 0x7FFF/14336 ~ 2.28 ticks; full_cycle_hz = 44100/(2*2.28) ~ 9672 Hz. Compute all entries with the verified counter-accumulate formula (matching the exact same math as 44-01 SUMMARY corrections). The table should produce entries ranging from approximately 37 Hz (shift 8, step 3) up to approximately 7350 Hz (shift 0, step 0). Use struct AmHzEntry with same fields as TremoloHzEntry.
  - Create hzToShiftAm(float hz) function using the same log-distance nearest-match algorithm as hzToShift but referencing kAmHzTable. Clamp to table boundaries.

  In PluginProcessor.cpp processBlock (AFTER the auto-pan block, BEFORE marker position update):
  - Add AM activation block inside its own scope, following the exact same three-branch pattern as tremolo:
    Branch 1 (amEn and not amWasActive): AM just enabled. Read amRateHz, amCurve atomics. Clamp Hz to table range. Call hzToShiftAm. Configure BOTH L and R sweeps identically (same direction, same shift, same step) with retrigger_enable=1. Both channels in sync (like tremolo). Direction=1 (decrease from current vol). Set amWasActive=true, store lastAmHz, lastAmCurve.
    Branch 2 (amEn and amWasActive): parameter change detection. If hz or curve changed, reconfigure both sweeps.
    Branch 3 (not amEn and amWasActive): deactivate both sweeps (active=0), set amWasActive=false.
  - After the three branches, add depth scaling (same formula as tremolo): vol = 0x7FFF - (0x7FFF - sweep_level) * depth.

  Mutual exclusion logic:
  - AM has LOWEST priority (tremolo wins over AM, auto-pan wins over AM). At the top of the AM block scope, load tremoloEnabled and autoPanEnabled; if either is true, treat amEn as false.
  - In the existing tremolo block: when tremolo activates and amWasActive is true, deactivate the AM state (set amWasActive=false, deactivate sweeps). Similarly in auto-pan block.
  - In the existing VCA ramp ARM logic: suppress ARM when amEnabled is true (same as existing tremolo check).

  NOTE: AM does NOT have L/R ratio. Both channels always run at the same rate (this differs from tremolo/auto-pan). AM produces sidebands; asymmetric rates would produce inharmonic beating which can be explored in a future phase if desired.
