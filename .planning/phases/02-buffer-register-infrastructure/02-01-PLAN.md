Create `scripts/ci/verify-no-heap-symbols.sh` matching the Phase 1 bash style:

```bash
#!/usr/bin/env bash
# scripts/ci/verify-no-heap-symbols.sh
# Phase 2 SC 1 + API-01: proves that libspu94.so does not import heap functions.
# Complements scripts/ci/grep-guard.sh (which checks source text only — the linker
# can still pull in malloc via a toolchain surprise).
#
# Exit codes: 0 = clean, 1 = forbidden symbol found, 2 = library not found.
#
# -----------------------------------------------------------------------------
# WHAT THIS CHECKS
# -----------------------------------------------------------------------------
# 1. `nm -u libspu94.so` lists undefined (= imported) symbols — what the library
#    asks the dynamic linker to resolve at load time.
# 2. `readelf -d libspu94.so` lists dynamic tags including NEEDED entries and
#    any relocations that reference external functions.
# Grepping both outputs for malloc|calloc|realloc|free catches both the
# "library imports heap" case and the "library has dynamic relocations to heap"
# case. Pitfall 8 (RESEARCH.md) documents why both are needed.

set -euo pipefail

LIB="${1:-build/src/spu94/libspu94.so}"

if [ ! -f "$LIB" ]; then
    echo "FAIL: $LIB not found — build libspu94 before running this script." >&2
    exit 2
fi

FAIL=0

# Pass 1: undefined symbols (nm -u)
if nm -u "$LIB" 2>/dev/null | grep -qE '\b(malloc|calloc|realloc|free)\b'; then
    echo "FAIL: $LIB references heap functions via undefined symbols:" >&2
    nm -u "$LIB" | grep -E '\b(malloc|calloc|realloc|free)\b' >&2 || true
    FAIL=1
fi

# Pass 2: dynamic relocations (readelf -d + readelf -r)
if readelf -r "$LIB" 2>/dev/null | grep -qE '\b(malloc|calloc|realloc|free)\b'; then
    echo "FAIL: $LIB dynamic relocations reference heap functions:" >&2
    readelf -r "$LIB" | grep -E '\b(malloc|calloc|realloc|free)\b' >&2 || true
    FAIL=1
fi

if [ "$FAIL" -ne 0 ]; then
    exit 1
fi

echo "OK: $LIB is heap-free (no malloc/calloc/realloc/free imports)."
exit 0
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller → spu94_init | Untrusted pointer + size crosses from caller memory into library. A mis-sized or mis-aligned pointer could cause UB in later Plans when internal fields are written. |
| Caller → work_buf | Untrusted pointer, potentially smaller than implied by `work_buf_size`. Phase 4+ reverb code will read/write into this region; Plan 01 only stores the pointer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `spu94_init` argument validation | mitigate | Reject NULL state_buf, undersized state_buf, misaligned state_buf, inconsistent work_buf args. Implement in Task 1; verify in Task 3 test_state_lifecycle suite. |
| T-02-02 | Denial of service | `spu94_reset` work-buffer zeroing loop | accept | An attacker-controlled `work_buf_size` up to 512 KB (PS1 SPU RAM max) could make reset O(N). Accepted: caller owns the size; the loop is bounded and deterministic; no amplification. |
| T-02-03 | Information disclosure | Stale bytes in caller-provided state_buf on init | mitigate | `spu94_init` zeroes fields via direct assignment before any read. `spu94_destroy` explicitly zeros the whole state via byte-loop for security hygiene. |
| T-02-04 | Elevation of privilege | `_Static_assert` sizeof guard bypass | mitigate | Compile-time assertion fails the build if `SPU94_STATE_SIZE_MAX` becomes too small. Cannot be bypassed at runtime; any future PR that grows the struct will either bump the macro (auditable) or fail CI. |
| T-02-05 | Spoofing | Symbol check pretends to pass but library actually imports heap | mitigate | Two-pass verification in `verify-no-heap-symbols.sh` (nm -u AND readelf -r) per RESEARCH.md Pitfall 8. Wired as a distinct CI job with its own green/red status. |
</threat_model>
