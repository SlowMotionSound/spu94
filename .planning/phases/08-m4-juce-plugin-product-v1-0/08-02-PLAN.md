```cpp
#pragma once
#include <JuceHeader.h>

struct LoadedWav {
    std::vector<int16_t> L;    // left channel, 44.1 kHz int16
    std::vector<int16_t> R;    // right channel, 44.1 kHz int16
    uint64_t numFrames = 0;    // number of stereo frames

    int originalNumChannels = 0;
    int originalBitsPerSample = 0;
};

namespace WavLoader {
    // Load any WAV file and normalize to 44.1 kHz int16 stereo.
    // Returns std::nullopt on failure (unreadable file, unsupported format).
    // Per D-06: bit-depth conversion (any -> int16), sample-rate conversion
    // (any -> 44.1 kHz via WindowedSincInterpolator), channel adaptation
    // (mono -> duplicate to stereo). SPU core stays bit-faithful.
    std::optional<LoadedWav> load(const juce::File& file);
}
```

**2. Create `src/standalone/WavLoader.cpp`:**

Implement `WavLoader::load()` following RESEARCH.md Pattern 7:

a) Create `juce::AudioFormatManager`, call `registerBasicFormats()` (covers WAV + AIFF, any bit depth).

b) Call `fmt.createReaderFor(file)` to get an `AudioFormatReader`. Return nullopt if nullptr.

c) Read all samples into a `juce::AudioBuffer<float>` sized to `(reader->numChannels, reader->lengthInSamples)`.

d) Call `reader->read(&srcBuf, 0, (int)reader->lengthInSamples, 0, true, reader->numChannels > 1)`.

e) Resample to 44.1 kHz using `juce::WindowedSincInterpolator` (per RESEARCH.md recommendation -- highest quality, latency irrelevant since resample is one-shot at load time):
   - If source SR == 44100.0 (within 1e-9), skip resampling
   - Otherwise compute `ratio = sourceSR / 44100.0` and `dstFrames = ceil(srcFrames / ratio)`
   - Create separate `WindowedSincInterpolator` per channel (Pitfall 7 -- per-channel state required)
   - Call `interp.process(ratio, srcPtr, dstPtr, dstFrames)` for each channel

f) Handle mono -> stereo: if source has 1 channel, duplicate L to R.

g) Convert float [-1, 1] to int16 [-32768, 32767]:
   - Scale by 32767.0f (NOT 32768 -- Pitfall 10)
   - Use `std::clamp` + `std::lround` for correct rounding with saturation
   - Lambda: `auto f2i = [](float x) -> int16_t { return (int16_t)std::clamp((int)std::lround(std::clamp(x, -1.0f, 1.0f) * 32767.0f), -32768, 32767); };`

h) Fill `LoadedWav` struct with the two int16 vectors, frame count, and original file metadata (SR, channels, bits).

**3. Update `src/standalone/CMakeLists.txt`:**

Add `WavLoader.cpp` to the `target_sources` list.

**Key implementation notes:**

- The WindowedSincInterpolator process() method signature is: `int process(double actualRatio, const float* inputSamples, float* outputSamples, int numOutputSamplesToConvert)`
- For files already at 44.1 kHz, bypass the interpolator entirely (copy path)

**2. Update `src/standalone/PluginProcessor.cpp`:**

a) `prepareToPlay(double sampleRate, int samplesPerBlock)`:
   - Allocate SPU state: `stateBuf.allocate(SPU94_STATE_SIZE_MAX, true)` and `workBuf.allocate(SPU94_WORK_BUF_MAX_BYTES, true)`
   - Call `spu94_init(stateBuf.getData(), SPU94_STATE_SIZE_MAX, workBuf.getData(), SPU94_WORK_BUF_MAX_BYTES)`
   - Call `spu94_load_preset(spu, SPU94_PRESET_HALL)` (sane default)
   - **Device sample rate constraint (RESEARCH.md Pitfall 8, option A):** After SPU init, check `sampleRate`. If it is NOT 44100.0, log a warning via `DBG("SPU-94: device sample rate is " << sampleRate << " Hz, expected 44100 Hz")`. The actual device constraint happens at startup (see step 2d below). The `prepareToPlay` assertion serves as a safety check: `jassert(std::abs(sampleRate - 44100.0) < 1.0)` -- this fires in debug builds if the device constraint failed, making the problem visible immediately instead of producing silently wrong-pitch audio.

b) `processBlock(juce::AudioBuffer<float>& buffer, juce::MidiBuffer&)`:
   - Check `newWavReady.load()`: if true, swap pending buffers into wavSource (the message thread set pendingL/R; audio thread consumes them). Set `wavSource.loaded = true`, `newWavReady = false`.
   - If not playing or not loaded: `buffer.clear(); return;`
   - Get `n = buffer.getNumSamples()`
   - Use stack-allocated int16 arrays for the per-block I/O (constexpr kMaxBlock = 4096; actual n from JUCE is smaller):
     ```cpp
     int16_t tmpL_in[kMaxBlock], tmpR_in[kMaxBlock];
     int16_t tmpL_out[kMaxBlock], tmpR_out[kMaxBlock];
     ```
   - Fill tmpL_in/tmpR_in from wavSource.L/R at current playPos. Handle loop: if playPos + n > numFrames, wrap around (continuous loop per RESEARCH.md Open Question 7 recommendation).
   - Call `spu94_process(spu, tmpL_in, tmpR_in, tmpL_out, tmpR_out, (uint32_t)n)`
   - Convert int16 output to float and write to JUCE buffer:
     ```cpp
     auto* outL = buffer.getWritePointer(0);
     auto* outR = buffer.getWritePointer(1);
     for (int i = 0; i < n; ++i) {
         outL[i] = tmpL_out[i] / 32768.0f;
         outR[i] = tmpR_out[i] / 32768.0f;
     }
     ```
   - Advance playPos: `wavSource.playPos.store((playPos + n) % wavSource.numFrames)`
   - No allocations, no locks, no syscalls in processBlock (Pitfall 1).

c) `loadWavFile(const juce::File& file)` (message thread):
   - Call `WavLoader::load(file)`
   - If successful, store result into pendingL/pendingR/pendingFrames
   - Set `newWavReady = true`
   - Do NOT directly write to wavSource -- the audio thread does the swap to avoid races

d) **Device sample rate constraint at startup:** Override `createEditor()` to also constrain the audio device. In the Standalone wrapper, the `AudioDeviceManager` is accessible via `juce::StandalonePluginHolder::getInstance()`. Add a helper method `constrainDeviceSampleRate()` called from the constructor or from `prepareToPlay` on first call:

```cpp
void SPU94AudioProcessor::constrainDeviceSampleRate()
{
    // RESEARCH.md Pitfall 8 option (A): constrain device to 44.1 kHz.
    // The JUCE Standalone wrapper owns the AudioDeviceManager.
    // StandalonePluginHolder is available when running as standalone.
    if (auto* holder = juce::StandalonePluginHolder::getInstance())
    {
        auto setup = holder->deviceManager.getAudioDeviceSetup();
        if (std::abs(setup.sampleRate - 44100.0) > 1.0)
        {
            setup.sampleRate = 44100.0;
            holder->deviceManager.setAudioDeviceSetup(setup, true);
            DBG("SPU-94: constrained audio device to 44100 Hz");
        }
    }
}
```

Call `constrainDeviceSampleRate()` from the SPU94AudioProcessor constructor. If `StandalonePluginHolder::getInstance()` returns nullptr (e.g., running in a test harness), the constraint is skipped silently -- the `jassert` in `prepareToPlay` catches it in debug builds.

e) `startPlayback()`: set `wavSource.playing = true`
f) `stopPlayback()`: set `wavSource.playing = false`, reset `wavSource.playPos = 0`
g) `releaseResources()`: call `spu94_destroy(spu); spu = nullptr;`
