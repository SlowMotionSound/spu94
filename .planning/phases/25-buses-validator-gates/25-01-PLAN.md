<objective>
Declare mono-mono, mono-stereo, and stereo-stereo bus layouts in the plugin processor and handle mono I/O in processBlock. Add the CLAP "mono" feature tag. Create unit tests for bus layout acceptance/rejection and mono summing accuracy.

Purpose: The SPU-94 engine always runs stereo internally, but DAW hosts need to place it on mono tracks (Logic, Reaper mono bus). Without isBusesLayoutSupported, the plugin only accepts stereo-stereo (JUCE default). This plan makes the plugin usable on mono tracks and verifiable by auval (PLUG-36).

Output: Modified PluginProcessor with bus layout support + mono processBlock path; two new CTest targets (test_bus_layout, test_mono_sum); CLAP features updated.

    Insert `bool isBusesLayoutSupported(const BusesLayout& layouts) const override;` among the existing public AudioProcessor overrides (after processBlock, before createEditor).

    B) PluginProcessor.cpp — Two additions:

    B1) isBusesLayoutSupported implementation. Place it after the constructor. The override whitelists exactly three configurations using AudioChannelSet comparisons:
    - mono in + mono out: return true (PLUG-32, PLUG-34)
    - mono in + stereo out: return true (PLUG-32, PLUG-33)
    - stereo in + stereo out: return true (PLUG-32)
    - disabled in or disabled out: return false
    - everything else (surround, Atmos, sidechain, multi-bus): return false (PLUG-35)

    The logic: get mainIn and mainOut from layouts.getMainInputChannelSet() / getMainOutputChannelSet(). Reject disabled. If mono in, accept mono or stereo out. If stereo in, accept only stereo out. All else false.

    Do NOT change the BusesProperties constructor — it stays stereo/stereo as the default layout. The override handles negotiation.

    B2) processBlock plugin path mono output handling. In the plugin path (the else branch after `if (isStandalone)`), modify the output section. Currently hostOutPtrs[1] is set to nullptr for mono output, which means SrcChain::processOut skips writing R data — that R data is lost, making mono summing impossible.

    Fix: declare a stack-allocated scratch buffer `float monoRScratch[kMaxBlock];` alongside the existing coreInL/coreInR/coreOutL/coreOutR stack arrays (same pattern, same scope). Detect mono output via `const bool monoOutput = (buffer.getNumChannels() == 1);`. When monoOutput is true, set hostOutPtrs[1] to monoRScratch instead of nullptr. This captures the R channel into the scratch buffer.

    After srcChain_.processOut returns AND after the under-produce padding block (lines 606-617), if monoOutput is true: also pad monoRScratch for the same range (hostNOut to n) using the last R sample. Then sum: for i in 0..hostNOut-1 (or n if padded), write `buffer.getWritePointer(0)[i] = (hostOutPtrs[0][i] + monoRScratch[i]) * 0.5f;`.

    After mono summing, guard the side-channel limiter with `if (!monoOutput)` so it only runs for stereo output. For mono, the side channel is zero by definition after (L+R)/2 summing, making the limiter an identity transform — skipping it is correct and saves CPU.

    C) src/plugin/CMakeLists.txt — Change line 106 from `CLAP_FEATURES audio-effect stereo reverb` to `CLAP_FEATURES audio-effect mono stereo reverb`. This adds the CLAP "mono" feature tag so CLAP hosts show the plugin on mono tracks (Pitfall 6 from RESEARCH.md).
