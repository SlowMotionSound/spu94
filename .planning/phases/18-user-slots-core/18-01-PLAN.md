# Phase 18 Plan 01: User Slots — Core

Add 8 programmable waypoint slots at midpoint positions between Sony's 9 factory anchors. Empty slots are transparent (audio bit-identical to v1.5). Filled slots act as new interpolation breakpoints, turning the morph dial from a 9-position perceptual continuum into a user-customisable 17-position continuum.

## Rationale

The v1.5 morph engine produces a fixed perceptual continuum: 9 Sony presets, equal angular spacing, linear interpolation between adjacent neighbours. The user has no way to insert their own waypoints. This phase opens that door without disturbing the v1.5 baseline — a fresh project (all slots empty) is bit-identical to v1.5.

## Design

- 8 slots at positions 1/16, 3/16, 5/16, ..., 15/16 (midpoints of the 8 segments between Sony's 9 anchors at 0/16, 2/16, 4/16, ..., 16/16)
- Slot storage: `int16_t user_slots[8][35]` + `bool user_slot_filled[8]` on `spu94_state`
- `spu94_interp_set_morph(state, pos)` consults `user_slot_filled[]` and treats filled slots as additional waypoints — the position-to-segment math becomes a 17-anchor lookup
- INTERP-04 bit-identity bypass extends naturally: if `pos` lands exactly on a filled slot's centre, the engine writes the slot's stored register set verbatim (no rounding)

## Integration Note

The engine state mirroring follow-up (task 4) was discovered during Phase 19 integration: the JUCE morph-glide path uses a scratch `spu94_state` (engines[1]) to compute target registers, and that engine has its OWN per-instance `user_slots[][]`. Without mirroring writes from the live engine to the scratch engine, the glide path produces transparent Sony interp instead of the saved waypoint values. The fix lives in the JUCE bridge but the root architectural truth is documented here: user_slots are per-engine state, and any multi-engine consumer of the C core must mirror.
