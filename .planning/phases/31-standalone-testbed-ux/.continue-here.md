<context>
The ADSR system has three layers: (1) the C engine (spu94_adsr.c) which runs the authentic PS1 counter-mechanism, (2) the processor (PluginProcessor.cpp) which converts GUI knob values (0.0-1.0 floats) to register field values (shift/step/exp/dir) via buildAdsrConfig(), and (3) the editor (PluginEditor.cpp) which manages 5 knobs + 3 Exp toggles + 1 enable toggle, all feeding atomics that the processor reads on the audio thread.

The ADSR config is passed at key_on time for both GUI trigger (voice 0) and MIDI voices (voices 1-23). Register fields are also updated live on voice 0 during playback without resetting phase/level/counter, so parameter changes take effect on the current envelope phase.

The AdsrDisplay component (AdsrDisplay.h) simulates ~80000 ticks of the ADSR engine with 128x downsampling, auto-triggering key_off after sustain hold. It repaints on every knob/toggle change via refreshAdsrDisplay().

Key discussion from this session: Anthony initially didn't understand the PS1 sustain rate concept. Through sound recipe examples (cymbal self-decay, pad swell, texture evaporation), he understood it as "what does the sound do when nobody's touching it — rise, hold, or fall." This led to the Rise/Fall rename and the reference line concept (show sustain level as a horizon, with the envelope departing above or below it).
</context>
