    Create the packaging/ directory tree with four scripts:

    A) packaging/linux/install.sh -- a POSIX sh script (not bash) that:
       - Accepts an optional --uninstall flag
       - In install mode: copies SPU-94.vst3/ directory to ~/.vst3/SPU-94.vst3, copies SPU-94.lv2/ directory to ~/.lv2/SPU-94.lv2, copies SPU-94.clap file to ~/.clap/SPU-94.clap
       - Creates target directories (mkdir -p) if they do not exist
       - In uninstall mode: removes those three paths
       - Prints what it did to stdout (one line per format installed/removed)
       - Exits 0 on success, 1 on error
       - The script expects to be run from the extracted tarball root where the three plugin artifacts are siblings of the install.sh file itself (i.e., the tarball contains: install.sh, SPU-94.vst3/, SPU-94.lv2/, SPU-94.clap)
       - Make the script executable (chmod +x in the CI step that tars it)

    B) packaging/macos/create_pkg.sh -- a bash script that CI calls with one argument: the path to the build artifacts directory. It:
       - Creates a staging directory with the macOS standard component layout:
         root/Library/Audio/Plug-Ins/Components/SPU-94.component (entire AU bundle)
         root/Library/Audio/Plug-Ins/VST3/SPU-94.vst3 (entire VST3 bundle)
         root/Library/Audio/Plug-Ins/CLAP/SPU-94.clap (single file)
       - Runs pkgbuild with --root pointing to the staging dir, --identifier com.spu94project.spu94.pkg, --version using the tag name (passed as second argument or defaulting to 0.0.0), output file SPU-94.pkg
       - Cleans up the staging dir
       - The .pkg requires admin privileges at install time (acceptable per PITFALLS B4 -- AU needs system path)

    C) packaging/macos/create_dmg.sh -- a bash script that CI calls with one argument: the path to the build artifacts directory. It:
       - Creates a staging directory named "SPU-94 Beta" containing:
         SPU-94.component/ (AU bundle)
         SPU-94.vst3/ (VST3 bundle)
         SPU-94.clap (CLAP file)
         A symlink "Drag Components Here -> /Library/Audio/Plug-Ins/Components/"
         A symlink "Drag VST3 Here -> /Library/Audio/Plug-Ins/VST3/"
         A symlink "Drag CLAP Here -> /Library/Audio/Plug-Ins/CLAP/"
       - Runs hdiutil create with -volname "SPU-94 Beta", -srcfolder pointing to the staging dir, -ov -format UDZO, output file SPU-94.dmg
       - Cleans up the staging dir

    D) packaging/windows/spu94.iss -- an Inno Setup 6 script (.iss) that:
       - AppName=SPU-94, AppVersion={#MyAppVersion} (defined at compile time via /D flag), AppPublisher=SPU-94 Project
       - DefaultDirName={autopf}\SPU-94 (used only for uninstaller location)
       - DisableDirPage=yes (users do not pick a folder -- plugins go to fixed standard paths)
       - Declares three file entries:
         Source: "artifacts\VST3\SPU-94.vst3\*"; DestDir: "{commoncf}\VST3\SPU-94.vst3"; Flags: recursesubdirs
         Source: "artifacts\CLAP\SPU-94.clap"; DestDir: "{commoncf}\CLAP"
       - Creates uninstall entries that remove those paths
       - OutputBaseFilename=SPU-94-Setup
       - Sets ArchitecturesInstallIn64BitMode=x64compatible
       - No code signing (per project decision -- signing deferred)
       - LicenseFile and InfoBeforeFile are not required for beta
       - Compression=lzma2, SolidCompression=yes

    All four scripts should have a header comment block identifying them as SPU-94 Phase 26 packaging scripts.
