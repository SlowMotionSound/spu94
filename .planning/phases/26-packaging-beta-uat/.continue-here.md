# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: Ardour plugin scan cache — Ardour caches plugin scan results and window geometry. A VST3 scan crash (scan-result=2) occurred during this session. Stale cache entries may cause the host to give the editor wrong dimensions or refuse to show the plugin. Always clear `~/.cache/ardour8/vst/` AND remove SPU-94 entries from `~/.config/ardour8/plugin_metadata/scan_log` before re-testing.
- [ ] CONSTRAINT: Do not fight the host in resized() — calling setSize() inside resized() when the host gives a different size creates a fight loop. Ardour wins, the plugin loses, and the window gets worse. Tried and confirmed harmful.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| resized() size guard | Calling setSize(900,1100) inside resized() when dimensions don't match expected. Creates fight with host, makes sizing worse. | blocking | Never override host-provided size in resized(). Communicate preferred size via setResizable/constrainer APIs only. |
| Stale Ardour cache | Ardour caches scan results and blacklists crashed plugins (scan-result=2). Rebuilding the plugin .so without clearing cache means Ardour uses stale data. | advisory | Clear ~/.cache/ardour8/vst/ and SPU-94 entries from scan_log before each test cycle. |
