## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| FetchContent cache poisoning | `set(BUILD_TESTING OFF CACHE BOOL "" FORCE)` inside a FetchContent shim disables tests for the WHOLE project when the shim is included before `add_subdirectory(tests)`. Caught when a new test target silently didn't build during Phase 22 UAT — discovered only because the test added at the end of the session never ran. | advisory | Any future FetchContent shim that touches a globally-scoped CMake variable must save/restore around `FetchContent_MakeAvailable`. Pattern is in `cmake/libsamplerate.cmake` after commit `6a99676`. |
| Reporting latency without delaying the path | A plugin reporting a non-zero `setLatencySamples()` value while the actual signal path through it has zero delay produces "PDC over-compensation" — host delays parallel dry by N samples while plugin emits dry at sample 0, so wet leads dry by N. Null tests can never null; real-world dry+reverb mixes show transient pre-echo on dry contributions. | advisory | When adding a new path that contributes to `setLatencySamples()`, audit the signal flow to confirm the path is ACTUALLY delayed by the reported amount. Cross-correlation of plugin output vs input is the cheap measurement (see `tests/plugin/test_null_passthrough.cpp` for the harness). |

_Both rows are `advisory` — informative but not gating future work._

<decisions_made>

- **C core `latency_comp` is now two-stage.** Stage A (28-sample ADPCM-match delay, unchanged, gated on `latency_comp` + `adpcm_enabled`) keeps dry aligned with patina entering the reverb send. Stage B (NEW: 58-sample FIR-match delay on dry + ADPCM, gated on `latency_comp` only) keeps dry, ADPCM, and reverb time-aligned at the master mix. `setLatencySamples()` is now an accurate report of actual output latency for all mix configurations.
- **`latency_comp` OFF = period-accurate PS1 SPU behaviour preserved.** Both stages no-op; dry races ahead of reverb by the FIR group delay (the historically authentic smear). The Latency Comp toggle is the user-visible opt-in for modern-DAW correctness vs hardware fidelity, aligning with the project North Star (fixed-point quirks are the product; smoothing is opt-in).
- **PLUG-15 closure used a headless null-test harness** at two host SRs rather than a continued Ardour GUI session. 44.1 kHz fast-path nulls strict at −85 dBFS; 48 kHz uses an alignment + residual proxy because Ardour's integer-only PDC cannot null the 0.13-host-sample fractional misalignment with broadband content (host limitation, not a plugin defect — Reaper's fractional PDC would close that gap).
</decisions_made>
