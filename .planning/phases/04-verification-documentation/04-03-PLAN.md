**ADR-0047: ADPCM prediction rounding -- round-to-nearest via +32 bias before ASR**

Context: The ADPCM decode formula computes `(old * f0 + older * f1) >> 6`. The PS1 hardware adds +32 before shifting, which is round-to-nearest (0.5 ULP bias). Alternative: truncation (no bias), which rounds toward negative infinity for all cases.

Decision: `(old * f0 + older * f1 + 32) >> 6` -- add +32 rounding bias before the arithmetic right shift. This matches the documented psx-spx formula exactly.

Consequences: Matches every behavioral witness tested. Filter 1 with old=1000 produces 938 (with bias) vs 937 (without bias). The 1-LSB difference accumulates across blocks and causes audible drift on sustained tones.

Sources: psx-spx SPU ADPCM documentation, behavioral witness testing during Phase 1.

**ADR-0048: ADPCM shift 13-15 policy -- map to shift 9**

Context: The ADPCM header byte encodes shift as 4 bits (0-15), but the decode formula `nibble << (12 - shift)` is only meaningful for shift 0-12. Shift 13-15 would produce negative left-shift amounts. Two documented behaviors: (a) map to shift 9 (psx-spx), (b) undefined/crash.

Decision: `if (shift > 12) shift = 9;` -- map all out-of-range shifts to 9, matching psx-spx documentation. The encoder never produces shift 13-15 (searches 0-12 only).

Consequences: Decoder handles any block a PS1 game might have produced. Harmless for well-formed streams. Test coverage: test_decode_shift13_maps_to_9, test_decode_shift14_maps_to_9, test_decode_shift15_maps_to_9.

**ADR-0049: ADPCM filter 5-7 policy -- clamp to filter 4**

Context: The filter index field is 3 bits (0-7) but only 5 coefficient pairs (0-4) are defined. Filter indices 5-7 have no documented coefficients. Two options: (a) clamp to 4, (b) treat as filter 0, (c) undefined.

Decision: `if (filter > 4) filter = 4;` -- clamp to the highest defined filter. This matches emulator consensus (DuckStation, Mednafen behavioral output). The encoder never produces filter 5-7.

Consequences: Array access is always in-bounds. Decoder behavior is deterministic for any input. Test: test_decode_filter_clamp_5to4 verifies filter 5 produces same output as filter 4.

**ADR-0050: ADPCM division semantics -- arithmetic right shift (>>6), not division (/64)**

Context: The prediction formula divides by 64. In C, `>> 6` on a negative value is implementation-defined (arithmetic right shift = round toward -inf), while `/64` rounds toward zero. These differ for negative predictions. This is the same ambiguity as ADR-0001 (Q15 multiply) applied to the ADPCM domain.

Decision: Use `>> 6` (arithmetic right shift), consistent with ADR-0001 discipline. The existing `_Static_assert((-1 >> 1) == -1, ...)` in spu94_q15.h covers this assumption project-wide.

Consequences: All compilers targeting this project (gcc 11+, clang 14+, arm-none-eabi-gcc) emit ASR. The ADR-0001 static assert protects this assumption at compile time.

**ADR-0051: ADPCM encoder error metric -- sum of squared error (L2) in int64**

Context: The brute-force encoder evaluates 65 (filter, shift) combinations per block. The error metric determines which combination wins. Options: (a) sum of absolute error (L1/SAD), (b) sum of squared error (L2/SSE), (c) max absolute error (Linf). L2 penalizes large deviations more than L1, producing perceptually better results. int64 accumulation prevents overflow (28 samples x max error^2 = 28 x 65535^2 = ~1.2e11, fits int64).

Decision: `int64_t error += (int64_t)diff * (int64_t)diff;` -- sum-of-squared-error in int64. L2 metric, integer-only, no float.

Consequences: Perceptually good results without psychoacoustic modeling. int64 is overkill for single-block error but cheap and eliminates overflow analysis. Test: test_encode_decode_roundtrip_deterministic confirms consistent winner selection.

**ADR-0052: ADPCM encoder tiebreaking -- strict less-than with iteration order**

Context: When two (filter, shift) pairs produce identical SSE, the encoder must pick deterministically. Options: (a) explicit tiebreak rules, (b) rely on iteration order with strict `<`. With strict `<`, the first combination found with a given error value wins; subsequent ties are rejected.

Decision: `if (error < best_error)` (strict less-than). Outer loop iterates filter 0-4, inner loop iterates shift 0-12. This means: lowest filter wins first, then lowest shift within that filter. No explicit tiebreak logic needed -- iteration order IS the tiebreak.

Consequences: Deterministic across compilers and platforms. Bias toward lower filter indices (simpler prediction) and lower shifts (coarser quantization) on ties. Test: test_encode_decode_roundtrip_deterministic verifies identical output across two runs.

**ADR-0053: ADPCM tail block padding -- caller zero-pads to 28 samples**

Context: The final audio segment may have fewer than 28 samples. The encoder API accepts exactly 28 samples per call (spu94_adpcm_encode_block). Two options: (a) encoder handles short blocks internally, (b) caller zero-pads the final block before calling.

Decision: Caller is responsible for zero-padding the input array to 28 samples. The encoder always processes exactly SPU94_ADPCM_BLOCK_SAMPLES (28) samples. This matches the VAG writer implementation (spu94_vag_write_mono in vag.c) which zero-pads the final block.

Consequences: Simpler encoder API (fixed-size I/O). The VAG end-flag (block[1] bit 0) signals the decoder to stop; trailing zero-padded samples are discarded by the reader. This matches PS1 hardware behavior where the SPU reads fixed-size blocks and the end flag terminates playback.
