2. Regenerate the non-DAC goldens (reverb-only -- no --dac or --adpcm flags):
   ```bash
   cd "/home/ubuntu-studio/Desktop/PSX Reverb"

   ```
   This regenerates the 50 reverb-only goldens. If the 8x change leaked into non-DAC paths, the SHA-256 hashes would change.

3. For each of the 50 reverb golden .wav files, compute SHA-256 and compare against the existing .sha256 sidecar:
   ```bash
   cd tests/golden
   find . -path '*/off/*' -prune -o -name '*.wav' ! -path '*/dac/*' ! -path '*/adpcm/*' -print | while read f; do
     expected=$(cat "${f%.wav}.sha256" 2>/dev/null | awk '{print $1}')
     actual=$(sha256sum "$f" | awk '{print $1}')
     if [ "$expected" != "$actual" ]; then
       echo "MISMATCH: $f"
       exit 1
     fi
   done && echo "ALL 50 REVERB GOLDENS MATCH"
   ```

   ```bash
   cd "/home/ubuntu-studio/Desktop/PSX Reverb"
   python3 scripts/regenerate_goldens.py --adpcm
   ```

5. Verify ADPCM goldens match their sidecars (same SHA-256 comparison loop, but for `*/adpcm/*.wav` files).

6. If ALL 80 non-DAC goldens match, INT-03 is satisfied. If ANY mismatch is found, the 8x change has leaked into non-DAC paths -- this is a critical bug that must be investigated before proceeding.

Note: The regenerate script builds CLI output WAVs by shelling out to the `spu94` CLI binary.
