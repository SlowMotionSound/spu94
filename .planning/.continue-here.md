# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure during this session.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **Per-engine state requires explicit mirroring.** `user_slots[][]` live on the `spu94_state` struct, so `engines[0]` and `engines[1]` each have their own copy. Any operation that mutates user_slots on engines[0] (`saveUserSlot`, `clearUserSlot`, per-slot LOAD, full preset LOAD) MUST mirror the change to `engines[1]` — otherwise the glide path's `spu94_interp_set_morph(engines[1], pos)` sees empty slots and produces transparent Sony interp instead of the user's saved values. Diagnosed by audible bug where saved waypoints sounded generic in Macro but correct in Advanced.

**Do not add new operations that touch engines[0].user_slots without mirroring to engines[1].**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---|---|---|---|
| Per-engine state without explicit mirroring | Wrote user_slots only to engines[0] in saveUserSlot. Glide path uses engines[1] for spu94_interp_set_morph; engines[1].user_slots stayed empty forever, so glided morph treated every saved slot as transparent (Sony interp). Audible-but-silent-on-snap-path bug. | blocking | Mirror every user_slot mutation to engines[1] (saveUserSlot, clearUserSlot, file-drain per-slot path, file-drain full-preset path all do this now). |
| Synchronous spu94_apply_pending_writes mid-frame | Called from the needShadowSync handler to "force" engines[0] to morph target on Advanced entry. Caused an audible blip whenever engines[0] differed from target (which was always-the-case until the per-engine mirror bug was fixed). | advisory | spu94_apply_pending_writes is documented to be called from EXACTLY ONE location (first line of spu94_tick). Prefer letting the audio thread handle re-applies via morphReapplyPending. SAVE flush is the acknowledged exception (without it snapshot misses freshly-edited m/d). |
| Audio I/O gate above state management | processBlock's loaded/playing early-return originally skipped morph re-apply, shadow sync, and preset drains when no WAV was loaded -- so sliders and ticks didn't reflect engine state without audio playing. | advisory | All state management runs unconditionally now. Only the sample-read + spu94_process + output-mix loop is gated on loaded/playing. Don't move state management back below the gate. |
| TICK_LATCHED snapshot races | spu94_snapshot_registers reads only active reg_values[]. m/d-prefix edits are staged into pending_values[] until spu94_tick commits. Snapshot before tick fires captures pre-edit values. | advisory | saveUserSlot calls spu94_apply_pending_writes(engines[0]) before snapshot to ensure recent edits are committed. |

- **REVERT semantics = "clear this slot entirely"** (not just "discard in-session edits"). User-requested emergency clear. After REVERT the slot reverts to empty (tick goes dim) and the engine writes the v1.5 transparent-interp Sony state.

- **user_slots stored per-engine** — saveUserSlot, clearUserSlot, per-slot LOAD, full preset LOAD all mirror to engines[1] (the scratch engine the glide path uses for spu94_interp_set_morph). Without mirroring, the glide path treats every slot as empty.
- **All state management hoisted before audio-I/O gate** in processBlock. Sliders + tick colors must reflect engine state regardless of WAV/playback status.
- **Forced re-applies (LOAD, SAVE, REVERT) snap regardless of Morph Speed**. Action buttons need instantaneous feedback, not glide.
- **Glide-path morph re-apply syncs shadows from engines[1] (target)** instead of engines[0] (mid-slew). Sliders show the destination, not the in-flight.
- **Custom GritButtonLookAndFeel** for Int/Fract toggle. JUCE's LookAndFeel_V4 desaturates unfocused buttons (.9x vs 1.3x saturation); override always uses focused saturation so Int starts in the right shade of coral.
