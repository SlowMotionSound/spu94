**test_process_mixer.c** -- Tests for the mixer bus routing and fader math.

Tests to implement:

1. **test_mixer_faders_default_zero** -- After init, all 6 fader getters return 0. Verify via API (not struct inspection).

2. **test_mixer_fader_set_get** -- For each of the 6 faders: set to 0x4000, get returns 0x4000. Set to 0x7FFF, get returns 0x7FFF. Set to 0, get returns 0.

3. **test_mixer_fader_null_safety** -- Call all 6 setters with NULL state (no crash). All 6 getters with NULL return 0.

4. **test_mixer_input_gain_zero_produces_silence** -- Set input_gain to 0, all other faders to 0x7FFF. Feed 128 samples of constant 10000. Output must be all zeros (zero gain = silence, regardless of other fader positions).

5. **test_mixer_dry_only** -- Set input_gain=0x7FFF, dry_fader=0x7FFF, reverb_fader=0, dry_send=0, patina_fader=0, patina_send=0. Feed 128 samples of constant 10000. Output samples should be non-zero (dry bus passes through). No reverb since dry_send=0.

6. **test_mixer_reverb_only** -- Set input_gain=0x7FFF, dry_fader=0, dry_send=0x7FFF, reverb_fader=0x7FFF, patina_fader=0, patina_send=0. Load Hall preset. Feed 256 samples of impulse (sample 0 = 16000, rest = 0). After initial FIR group delay (~58 samples), some output should be non-zero from the reverb return. Early output (before reverb tail arrives) should be all zeros since dry_fader=0.

7. **test_mixer_three_bus_sum_saturation** -- Set all three faders to 0x7FFF, input_gain to 0x7FFF, dry_send to 0x7FFF, patina_send to 0x7FFF. Enable ADPCM. Feed samples that would cause all three buses to contribute maximally. The output should saturate at INT16_MAX / INT16_MIN rather than wrap (hard clip behavior verified by sat_s16).

8. **test_mixer_state_size_under_cap** -- `spu94_state_size() <= SPU94_STATE_SIZE_MAX`.

**test_process_dac_integration.c** -- Tests for DAC toggle hierarchy and DAC processing.

Tests to implement:

1. **test_dac_toggles_default_off** -- After init: `spu94_get_dac_enabled(state) == 0`, `spu94_get_dac_fir_enabled(state) == 0`, `spu94_get_dac_noise_enabled(state) == 0`.

2. **test_dac_toggle_set_get** -- For each of the 3 DAC toggles: set to 1, get returns 1. Set to 0, get returns 0. Set to 42, get returns 1 (normalize to 0/1).

3. **test_dac_toggle_null_safety** -- All 3 setters with NULL (no crash). All 3 getters with NULL return 0.

4. **test_dac_master_off_bypasses_processing** -- Set up unity passthrough. Enable DAC master=0, FIR=1, noise=1. Feed 256 samples through spu94_process. Save output as baseline. Then enable DAC master=1 on a fresh state with same faders. Feed same input. Output should DIFFER from baseline (FIR and noise alter the signal). This proves master toggle gates sub-features.

5. **test_dac_fir_only** -- Enable DAC master=1, FIR=1, noise=0. Feed 256 samples. Compare with baseline (DAC off). Output should differ (FIR alters signal). Verify by checking that at least some samples differ.

6. **test_dac_noise_only** -- Enable DAC master=1, FIR=0, noise=1. Feed 256 samples. Compare with baseline. Output should differ (noise adds to signal).

7. **test_dac_both_on_differs_from_each_alone** -- Three runs: FIR-only, noise-only, both-on. All three outputs should be mutually different (at least some samples differ between each pair).

8. **test_dac_state_reset_on_disable** -- Enable DAC master, enable FIR and noise, feed 100 samples. Disable DAC master. Inspect struct directly: `state->dac_fir_l.stage1_idx == 0` (FIR state zeroed), `state->dac_noise_l.lfsr != 0` (noise state re-initialized with non-zero seed, not zeroed).

9. **test_dac_noise_decorrelated_channels** -- Enable DAC master + noise. Feed 256 samples of silence (input_gain=0). Read L and R outputs. At least some samples should differ between L and R (proving different seeds per channel from WR-02 fix). Note: with input_gain=0, all signal is zero, but noise is added unconditionally when enabled. Actually -- check the signal flow. DAC section processes the master mixer output. If input_gain=0, the master mixer output is zero. Noise is ADDED to zero, so output = noise samples only. L and R should differ because L uses seed 0xACE1 and R uses seed 0x1ECA.

**test_process_latency_comp.c** -- Tests for the 28-sample latency compensation delay.

Tests to implement:

1. **test_latency_comp_default_on** -- After init: `spu94_get_latency_comp(state) == 1` (D-07).

2. **test_latency_comp_set_get** -- Set to 0, get returns 0. Set to 1, get returns 1. Set to 42, get returns 1.

3. **test_latency_comp_null_safety** -- Setter with NULL (no crash). Getter with NULL returns 0.

4. **test_latency_comp_only_when_adpcm_enabled** -- Set up unity passthrough. ADPCM disabled, latency_comp=1. Feed 128 samples of constant 10000. Save output. Then on a fresh state, set ADPCM disabled, latency_comp=0. Feed same input. Output should be identical (latency comp does nothing when ADPCM is off, per Pitfall 5).

5. **test_latency_comp_delays_dry_28_samples** -- Enable ADPCM and latency_comp=1. Set input_gain=0x7FFF, dry_fader=0x7FFF, dry_send=0, reverb_fader=0, patina_fader=0. Feed 64 samples where sample 0 = 10000 and rest = 0. The dry bus output should show the impulse delayed by 28 samples. Specifically: output samples 0-27 should be 0 (delay buffer initially zero), and output sample 28 should be non-zero (the impulse emerges from the delay). Note: this requires reverb_fader=0 and patina_fader=0 so only dry bus contributes to output.

6. **test_latency_comp_off_no_delay** -- Same setup as above but latency_comp=0. The impulse should appear at the output without the 28-sample delay (dry bus passes through directly).

7. **test_latency_comp_state_reset_on_disable** -- Enable latency_comp. Feed 14 samples. Check `state->delay_pos == 14` via struct inspection. Disable latency_comp. Check `state->delay_pos == 0` and `state->delay_buf_l[0] == 0` (delay buffer zeroed on disable).
