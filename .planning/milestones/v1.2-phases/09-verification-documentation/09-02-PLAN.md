Create `tools/dac_measure.py` — a single-script DAC characterization report per D-06/D-07/D-08.

**Structure:**

1. **Imports and constants:**
   - numpy, scipy.signal, scipy.io.wavfile, subprocess, tempfile, pathlib, hashlib, argparse, sys
   - matplotlib (import inside plot function, with Agg backend for headless)
   - FS = 44100, SWEEP_DURATION = 2.0

2. **`locate_cli()`** — reuse same pattern as regenerate_goldens.py (check $SPU94_BIN, then build/src/cli/spu94, then PATH)

3. **`get_design_coefficients()`** — import the three stage coefficient sets from dac_filter_design.py. Do this by adding `tools/` to sys.path and calling `design_halfband_stage` for each of the three stages: (55, 352800, 88200), (11, 176400, 44100), (7, 88200, 22050). Then call `build_composite` and `quantize_to_q15` to get the Q15 composite. Return both float composite and Q15 composite.

4. **`measure_frequency_response(spu94_bin)`** — per D-06:
   - Generate a logarithmic sweep 20Hz-20kHz, 2 seconds, int16, stereo, at 44100 Hz
   - Write to temp WAV
   - Run `spu94 reverb --dac --no-dac-noise <input.wav> <output.wav>` (FIR only, no noise, no reverb/Off preset by default)
   - Read output WAV
   - Compute magnitude spectrum of output vs input using FFT (use welch or periodogram for smoother estimate)
   - Also compute analytical response from Q15 coefficients via `scipy.signal.freqz(q15_coeffs / 32768.0, worN=8192, fs=44100)`
   - Return frequency arrays and magnitude arrays for both measured and analytical curves

5. **`measure_noise_slope(spu94_bin)`** — per D-08:
   - Generate silence (all zeros), 2 seconds, int16, stereo
   - Run `spu94 reverb --dac --no-dac-fir <input.wav> <output.wav>` (noise only, no FIR)
   - Read output WAV — the nonzero samples are pure DAC noise
   - Compute power spectral density (welch, nperseg=4096)
   - Fit a line to log-log PSD from 1kHz-20kHz
   - Return slope_dB_per_octave, freq_array, psd_array

6. **`check_passband_ripple(freq, mag_dB)`** — per D-07 check 1:
   - Find indices where 10000 <= freq <= 20000
   - Compute max deviation from 0 dB in that band
   - Assert deviation <= 0.078 dB (Phase 5 documented tolerance)
   - Return (pass/fail, max_deviation_dB)

7. **`check_design_deviation(freq, measured_dB, analytical_dB)`** — per D-07 check 2:
   - At each frequency point, compute |measured - analytical|
   - Assert max deviation <= 0.5 dB (Claude's discretion: tight enough to catch real drift, loose enough for quantization noise + FFT estimation error at 44.1kHz)
   - Return (pass/fail, max_deviation_dB, freq_at_max)

8. **`check_noise_slope(slope_dB_per_octave)`** — per D-08:
   - Assert slope is within 12 +/- 3 dB/octave (2nd-order HP shape)
   - Return (pass/fail, measured_slope)

9. **`plot_report(freq_measured, mag_measured, freq_analytical, mag_analytical, noise_freq, noise_psd, output_path)`** — per D-08 specifics:
   - Two subplots in one figure:
     - Top: filter magnitude response. X = frequency (Hz, log scale). Y = magnitude (dB). Two curves: "Measured (C engine)" in blue, "Analytical (Q15 freqz)" in orange dashed. Y limits -3 to +0.5. Vertical lines at 10kHz and 20kHz marking the top-octave region.
     - Bottom: noise spectral slope. X = frequency (Hz, log scale). Y = PSD (dB). Overlay a +12dB/octave reference line.
   - Save as `tools/dac_measure.png`
   - figsize=(10, 8), tight_layout

10. **`main()`:**
    - argparse with `--plot` (default: run checks only, skip plot), `--verbose`
    - Run measure_frequency_response, measure_noise_slope
    - Run all three checks, print PASS/FAIL for each with values
    - If --plot: generate and save the PNG
    - Exit 0 if all checks pass, exit 1 if any fail
    - Print summary: "DAC Characterization: 3/3 checks passed" or "DAC Characterization: N/3 checks FAILED"

**Test 1: `test_dac_on_off_on_bit_identical`** — D-10 item 1:
- Create two fresh states A and B
- Both: set_unity_passthrough, load_preset(hall), set_dac_enabled(1), set_dac_fir_enabled(1), set_dac_noise_enabled(1)
- State A: process 256 samples of deterministic input (same PRNG pattern as existing tests: `(i * 7919 + 1234) % 30000 - 15000`)
- State B: process same 256 samples, then disable DAC, then re-enable DAC (all 3 toggles), then process ANOTHER 256 samples of new deterministic input
- State A: also process the same second 256 samples
- Compare: the second batch of output from A and B must be bit-identical (DAC state reset on disable means re-enable starts from the same clean state)
- Note: both states had identical initial conditions, so after re-enable and state reset, they diverge only in reverb buffer contents. Use Off preset (no reverb) instead to isolate DAC behavior: `spu94_load_preset(s, 0)` for Off.

Corrected approach for bit-identity:
- Use Off preset (no reverb tail), unity passthrough
- State A: fresh init, DAC on, process 256 samples
- State B: fresh init, DAC on, process 256 samples to dirty state, DAC off (state reset), DAC on again, process 256 samples of SAME input as State A's first batch
- Output from State A (first 256) must match State B (post-re-enable 256) bit-for-bit, because both started from clean DAC state with identical input

**Test 2: `test_dac_reverb_interaction`** — D-10 item 2:
- Create two fresh states
- Both: set_unity_passthrough, load_preset(hall), set_dry_send(0x7FFF)
- State A: DAC disabled (default)
- State B: DAC enabled (all 3 sub-toggles on)
- Process 512 samples of same deterministic input through both
- Verify outputs differ (at least one sample differs). This catches wiring bugs where DAC silently no-ops when reverb is active.

**Test 3: `test_dac_adpcm_composition`** — D-10 item 3:
- Create fresh state
- Set: set_unity_passthrough, load_preset(room), set_patina_fader(0x7FFF), set_adpcm_send(0x7FFF)
- Enable both DAC (all 3 toggles) and ADPCM (`spu94_set_adpcm_enabled(state, 1)`)
- Process 512 samples of deterministic input
- Create second state with only DAC enabled (no ADPCM)
- Create third state with only ADPCM enabled (no DAC)
- All three outputs should differ from each other (both coloration stages compose, not stomp)

**Test 4: `test_dac_fir_sub_toggle_transitions`** — Additional toggle coverage:
- Fresh state, Off preset, unity passthrough
- Enable DAC master + both sub-toggles, process 256 samples
- Disable only FIR sub-toggle (noise still on), process 256 more
- Re-enable FIR sub-toggle, process 256 more
- Verify: the re-enabled output is not all-zeros (FIR is actually processing again)
- Verify: the noise-only segment differs from the both-on segments
