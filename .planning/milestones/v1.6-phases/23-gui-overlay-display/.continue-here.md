# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: GUI-layer snap resolution causes register overwrites — Two attempts to resolve 0xFF "Global" to the actual global subdivision in PluginProcessor.cpp were reverted. Both caused all echo speed registers to snap to 0 because: (a) BPM may not be set in the C core (tempo_bpm=0 makes spu94_set_subdivision return INVALID_ARG), (b) resolving 0xFF pushes subdivisions that overwrite preset echo speed values on mode transitions. The fix MUST live in the C core snap module, not the GUI layer.

- [ ] CONSTRAINT: Timer-driven knob position sync causes snap-back — Reading derived atomics every 33ms and writing to knobs overwrites user drags. Knob positions must only sync on derive-all events (preset load, view switch) via the knobsNeedSync flag. Wall knobs are an exception (sync from register shadows every tick with isMouseButtonDown guard) because they track Room Size changes.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| GUI-layer snap resolution | Resolving 0xFF to global subdivision in processBlock dropdown push causes register overwrites when BPM=0 or mode transitions fire. Two attempts, two reverts. | blocking | Fix must add global_subdivision field to spu94_state in C core so snap module resolves 0xFF internally at apply time, not at push time |
| Timer knob overwrite | Timer reading derived atomics and calling setValue on knobs every 33ms fights user drags and causes snap-back to stale values | blocking | Use knobsNeedSync atomic flag — only set true by processBlock after derive-all. Timer checks and clears the flag before updating knobs |
| Unsigned register overflow in GUI | m-prefix and d-prefix registers are uint16_t (0-65535) but RegisterBridge shadows use int16_t. Values above 32767 appear negative in GUI, causing knobs to snap to 0 | advisory | Cast shadow reads to uint16_t before setting knob values. Knob ranges must be 0-65535, not 0-32767 |
| Missing macro group registration | spu94_macro_controls_register_all() was never called from PluginProcessor constructor. All Spread+Sweep apply functions silently returned INVALID_ARG | advisory | Call spu94_macro_controls_register_all(spu) immediately after spu94_load_preset in constructor |

<decisions_made>

- Wall distance knobs are interactive, not read-only — user shapes individual walls in Room Designer. Clamped by buffer boundary (safety layer), not by Room Size.
- Buffer knob inverted in GUI — up = max space, down = crush. Macro engine works internally with position 0 = max space; GUI inverts with `1.0f - position`.
- Subdivision dropdowns removed from MacroPanel — already in toolbar, user confirmed they were clutter.
- Manual register changes refresh Spread+Sweep references — without this, Echo Physics Sweep operates on old preset references, not the user's custom wall settings.
- Knob positions only sync from derived atomics on derive-all events — prevents timer from fighting user drags.
- Echo Physics Spread/Sweep moving wall echo knobs is correct behavior — they operate on the same d-prefix registers displayed by the wall echo knobs.
- Rotate only works in Sync mode (Free mode has no grid positions to permute) — by design from Phase 22.
</decisions_made>
