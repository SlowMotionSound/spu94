<objective>
Build the macro engine in the C core: group definitions, proportional scaling from current state, gang clamping, dynamic knob range, and re-derivation of knob position from raw register state. The engine uses the safety layer from Plan 01 for all register writes. Phase 21 wires up the 8 specific macro control definitions through this engine.

Purpose: Transform 35 raw registers into coordinated groups that move proportionally when a single knob sweeps. This is the foundation that makes the instrument playable -- the difference between tweaking 14 individual sliders vs turning one Room Size knob.

Output: `spu94_macro.h` (public API), `spu94_macro.c` (engine implementation), state struct additions, and 4 test suites covering proportional scaling, gang clamping, dynamic range, re-derivation, and ratio preservation.

    Proportional scaling (MACRO-01, test_macro_group.c):
    - Register group with 3 U16 members: reg A base=1000 floor=0 ceil=10000, reg B base=2000 floor=0 ceil=10000, reg C base=3000 floor=0 ceil=10000. Derive at current state -> position ~0.3 (most constrained: C at 3000/10000). Apply position=0.5: A -> 1000 + (1000/3000)*(5000-3000) = ~1667, B -> 2000 + (2000/3000)*2000 = ~3333, C -> 5000. Ratios preserved: A:B:C = 1:2:3 at any position.
    - Actually the proportional scaling math: derive captures base values. Position 0.0 = all at floor. Position 1.0 = most-constrained at ceiling. Apply at position P: each register = floor + (base_ratio * P * effective_range), where base_ratio = (base - floor) / (most_constrained_base - floor), and effective_range = most_constrained_ceiling - floor... This needs careful definition.
    - SIMPLER MODEL: position 0.0 = all at floor, position 1.0 = all at their respective ceilings (but gang-clamped so the first one to hit ceiling stops everyone). Base values define the RATIOS. The derive function computes position from the most-constrained register's fraction between floor and ceiling.
    - Even simpler: position maps linearly. At position P, each register value = floor[i] + P * (ceiling[i] - floor[i]) * ratio[i], where ratio[i] is normalized such that the most-constrained register has ratio 1.0 and others have ratio <= 1.0 proportional to their base headroom fraction.
    - CLEANEST MODEL from RESEARCH.md: "base_values" snapshot at derive time. "knob_position" represents the fraction of the most-constrained register's travel. Apply: for each member, new_value = base_value[i] + (knob_delta * headroom[i]), where headroom[i] = ceiling[i] - base_value[i] for upward, base_value[i] - floor[i] for downward. But this doesn't preserve ratios if the base values have different headroom fractions.
    - CORRECT APPROACH (from CONTEXT.md "Ratio preservation: proportional scaling, not absolute positioning"): The knob moves ALL registers by the SAME FRACTION of their available headroom. This preserves ratios. At derive, compute each register's fraction = (current - floor) / (ceiling - floor). The knob position = the minimum of these fractions (most constrained). Apply at position P: for each register, new_value = floor + P * (ceiling - floor). Wait, that makes all registers the same fraction -- it DOESN'T preserve ratios between registers. If reg A is at fraction 0.3 and reg B at fraction 0.5, moving both to fraction P would change their ratio.
    - Re-reading CONTEXT.md: "Ratio preservation: if a user hand-sculpts register ratios in raw mode, macro sweep preserves those ratios via proportional scaling." The key word is PROPORTIONAL. If base values are A=1000, B=2000, C=3000, and all have floor=0 and ceil=65535, then sweeping proportionally means multiplying all by the same factor. Knob at 0.5 = scale factor 0.5 -> A=500, B=1000, C=1500. Knob at 2.0 = scale factor 2.0 -> A=2000, B=4000, C=6000. The knob maps to a SCALE FACTOR relative to the base values.
    - With floors and ceilings: the scale factor can go from (floor/max_base) to min(ceiling[i]/base[i]) for all i. Gang clamp: the register with the smallest ceiling/base ratio defines the max scale factor.
    - ZERO HANDLING: if base[i] = 0, that register stays at 0 during any sweep (you can't scale zero proportionally). This matches RESEARCH.md Pitfall 4: "Zero base values mean the register has no contribution to the group."
    - This is the correct model: position 0.0 = scale factor 0 (all at zero, or floor if floor != 0). Position 1.0 = scale factor at the gang-clamp ceiling. Apply: for each register, new_value = base[i] * scale_factor. But we need to handle floors...
    - WITH FLOORS: offset-then-scale. base_offset[i] = base[i] - floor[i]. new_value = floor[i] + base_offset[i] * scale_factor. The scale factor range: min = 0.0 (all at floor), max = min over all i of (ceiling[i] - floor[i]) / base_offset[i] (for base_offset[i] > 0). The knob position [0.0, 1.0] maps to scale_factor [0.0, max_scale]. Actually position = scale_factor / max_scale (normalized).
    - RE-DERIVATION: current_offset[i] = current[i] - floor[i]. If all offsets are proportional to base_offsets (which they should be after a macro sweep), then scale_factor = current_offset[i] / base_offset[i] for any i. Position = scale_factor / max_scale. Use the most-constrained register (smallest ratio) for robustness.
    - DERIVE also captures base values. When derive is called, the current register values BECOME the new base values. The position is then 1.0 (since current = base = the starting point, scale factor = 1.0, and position = 1.0 / max_scale... no, if derive sets base to current, then scale factor = 1.0 at the derive point, and position = 1.0 / max_scale. That's not intuitive.)
    - ALTERNATIVE DERIVE: position represents fraction of total range. Derive captures current values. The position after derive = fraction of most-constrained register between floor and ceiling. e.g. if most-constrained is at 3000 with floor=0, ceiling=10000, then position = 3000/10000 = 0.3. Apply at position 0.3 reproduces the derived state. Apply at position 0.6 doubles the offset from floor for ALL registers proportionally.
    - YES. This is the model:
      - derive: base_values = current register values. For each member, fraction = (current - floor) / (ceiling - floor). Position = min(fraction) (most constrained). Store base values and position.
      - apply(P): For each member, compute target fraction = P. But WAIT -- this makes all registers the same fraction, losing ratios.
      - NO. The model must preserve ratios. Let me think again.

                                    const int32_t *base_values) {
        float max_scale = 1e30f;  /* effectively infinity */
        for (int i = 0; i < group->member_count; i++) {
            int32_t offset = base_values[i] - group->members[i].floor;
            if (offset <= 0) continue;  /* at floor or below -- infinite headroom upward, skip */
            int32_t headroom = group->members[i].ceiling - group->members[i].floor;

        if (state == NULL) return 0.0f;
        if ((int)group_id < 0 || (int)group_id >= SPU94_MACRO_GROUP__COUNT) return 0.0f;
        const spu94_macro_group_t *group = state->macro_group_defs[group_id];

        for (int i = 0; i < group->member_count; i++) {
            state->macro_base_values[group_id][i] =
                read_member_value(state, &group->members[i]);
        }

        /* Compute max_scale and position */
        float max_scale = compute_max_scale(group,
                                             state->macro_base_values[group_id]);
        float position;
        if (max_scale <= 0.0f || max_scale > 1e20f) {

             * Knob position = 1.0 / max_scale (fraction of full travel). */

            if (position > 1.0f) position = 1.0f;
            if (position < 0.0f) position = 0.0f;

        return position;

    `spu94_macro_apply`:
    ```c
    spu94_result_t spu94_macro_apply(spu94_state *state,
                                      spu94_macro_group_id_t group_id,
                                      float position) {
        if (state == NULL) return SPU94_INVALID_STATE;
        if ((int)group_id < 0 || (int)group_id >= SPU94_MACRO_GROUP__COUNT)
            return SPU94_INVALID_ARG;
        const spu94_macro_group_t *group = state->macro_group_defs[group_id];
        if (group == NULL) return SPU94_INVALID_ARG;

        /* Clamp position to [0, 1] */
        if (position < 0.0f) position = 0.0f;
        if (position > 1.0f) position = 1.0f;

        float max_scale = compute_max_scale(group,
                                             state->macro_base_values[group_id]);
        if (max_scale <= 0.0f) max_scale = 1.0f;  /* degenerate: no-op */

        float scale_factor = position * max_scale;

        /* Re-entrancy guard: prevent hooks from re-entering during batch write */
        state->macro_writing = 1;

        spu94_result_t worst = SPU94_OK;
        for (int i = 0; i < group->member_count; i++) {
            int32_t base_offset = state->macro_base_values[group_id][i] -
                                  group->members[i].floor;
            int32_t new_value;
            if (base_offset <= 0) {
                /* Zero or negative offset: stays at floor */
                new_value = group->members[i].floor;
            } else {
                /* Proportional: floor + base_offset * scale_factor */
                new_value = group->members[i].floor +
                            (int32_t)(base_offset * scale_factor + 0.5f);
            }
            spu94_result_t r = write_member_value(state, &group->members[i], new_value);
            /* Track the "worst" result: safety clamped > OK */
            if (r != SPU94_OK && worst == SPU94_OK) worst = r;
        }

        state->macro_writing = 0;
        state->macro_knob_pos[group_id] = position;
        return worst;
    }
    ```
