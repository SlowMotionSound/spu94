<objective>
Build the safety enforcement layer as wrapper functions around the existing register setters. Two constraints enforced: (1) vIIR x vWALL product ceiling at 0x40000000 (Q15 unity squared), and (2) m-prefix address register bounds checking against work_buf_size. Both macro and raw mode writes will route through these safe setters (the macro engine in Plan 02 calls them; Phase 21+ GUI/CLI surfaces call them for raw mode).

Purpose: Prevent runaway IIR feedback (audio screech from divergent loop gain) and out-of-bounds reverb buffer access. These constraints must exist before the macro engine (Plan 02) can safely sweep registers.

Output: `spu94_safety.c` with `spu94_safe_set_reg_i16` and `spu94_safe_set_reg_u16` wrapper functions, two new result codes in `spu94.h`, and two test suites proving both constraints.
</objective>

    `spu94_safe_set_reg_i16` implementation:
    - NULL and range guards (same as spu94_set_reg_i16 but return early)
    - If reg is SPU94_REG_vIIR: read current vWALL from `state->reg_values[SPU94_REG_vWALL]` (IMMEDIATE register, so reg_values is latest). Compute `int32_t product = abs_i32_safe(value) * abs_i32_safe(vWALL)`. If `product > SPU94_STABILITY_LIMIT`: compute `int32_t abs_wall = abs_i32_safe(vWALL)`, if abs_wall == 0 skip (no constraint), else `int32_t max_abs = SPU94_STABILITY_LIMIT / abs_wall`, clamp value to `[-max_abs, max_abs]` preserving sign, call `spu94_set_reg_i16(state, reg, clamped_value)`, return `SPU94_STABILITY_CLAMPED`.
    - If reg is SPU94_REG_vWALL: symmetric check against current vIIR from `state->reg_values[SPU94_REG_vIIR]`.
    - Otherwise: pass through to `spu94_set_reg_i16(state, reg, value)` and return its result.

    `spu94_safe_set_reg_u16` implementation:
    - NULL and range guards
    - If `is_m_prefix_addr(reg)` AND `state->work_buf_size > 0`: compute `uint16_t max_halfword = (uint16_t)((state->work_buf_size / 2) - 1)`. If `value > max_halfword`: call `spu94_set_reg_u16(state, reg, max_halfword)`, return `SPU94_ADDRESS_CLAMPED`.
    - Otherwise: pass through to `spu94_set_reg_u16(state, reg, value)` and return its result.
    - Note: mBASE is NOT in m_prefix_addr_mask (mBASE is a base pointer, not a room-size address offset). d-prefix registers (dAPF1, dAPF2, dLSAME, etc.) are NOT address registers; they are delay OFFSETS from the corresponding m-prefix address. d-prefix registers pass through without bounds checking.
