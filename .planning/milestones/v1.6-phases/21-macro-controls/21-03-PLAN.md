  1. `spu94_macro_apply_decay(state, position)`:
     - Call `spu94_macro_apply_bipolar(state, SPU94_MACRO_DECAY, position)`.
     - After the write, check if REFLECTIVITY group is registered (`spu94_macro_group_registered`).
     - If so, call `spu94_macro_derive_bipolar(state, SPU94_MACRO_REFLECTIVITY)` to re-derive the Reflectivity knob position from the (possibly stability-clamped) vWALL value.
     - Return the result from the bipolar apply.

  2. `spu94_macro_apply_buffer(state, position)`:
     - Validate inputs. Clamp position to [0.0, 1.0].
     - Compute inverted mBASE value: `uint16_t new_mbase = (uint16_t)((1.0f - position) * (float)ceiling + 0.5f)` where ceiling is the Buffer group's member ceiling (0xFFFF, or a computed value based on work_buf_size -- check what the safety layer uses). Actually, per D-17: knob up = mBASE value down. position=1.0 -> mBASE=0 (floor). position=0.0 -> mBASE=ceiling.
     - Write mBASE via `spu94_set_reg_u16(state, SPU94_REG_mBASE, new_mbase)`. (mBASE is IMMEDIATE policy, no tick needed.)
     - Note: mBASE is NOT an m-prefix address register per the safety layer (spu94_safety.c excludes it from m_prefix_addr_mask). So the safe setter won't bounds-check mBASE itself.
     - After mBASE write, re-validate all m-prefix registers through the safety layer. For each m-prefix register, read current value and re-write through `spu94_safe_set_reg_u16`. The safety layer will clamp any that exceed the new `(work_buf_size / 2) - 1` boundary. Note: the safety layer uses work_buf_size for m-prefix bounds, NOT mBASE. Check whether mBASE affects the safety boundary. If mBASE doesn't affect the safety layer's bounds check (it uses work_buf_size), then the re-clamp is about the reverb body's internal addressing, not the safety layer. In that case, the effective ceiling for m-prefix when mBASE > 0 would be `(work_buf_size / 2) - 1 - mBASE`. This may require reading the safety layer's actual implementation to understand the relationship. Per Pitfall 3 in RESEARCH.md: "After Buffer apply, re-derive all macro groups that contain m-prefix registers."
     - After re-clamp pass, re-derive these groups: ROOM_SIZE, TAP_POSITION, DIFF_POSITION. Call `spu94_macro_derive` (unipolar) or appropriate derive function for each.
     - Store position in macro_knob_pos[BUFFER].

         - For bipolar single-register groups (Decay, Reflectivity): call `spu94_macro_derive_bipolar(state, g)`.
         - For unipolar single-register groups (Buffer): call `spu94_macro_derive(state, g)`.
         - For Room Size (unipolar multi-member but uses the Phase 20 linear apply): call `spu94_macro_derive(state, g)`.
     - Return SPU94_OK.
     - INVARIANT: No register value is modified. Test this by snapshotting all 35 registers before derive_all and asserting they match after.
