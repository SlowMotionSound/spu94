## Definition of Done (from ROADMAP)

> Let the player choose how many of the 24 sampler voices are active, and make the whole sampler play correctly at that count.

A 1–24 voice-count selector decides how many voices are live; per-voice controls apply across every active voice (not just voice 0); allocation respects the count (steal-oldest past the limit, mono last-note priority at 1); selector/controls/allocation stay in sync; and the count saves/restores with presets.

## Cross-Phase Integration (gsd-integration-checker)

**Clean.** 10 wiring links verified end-to-end; 0 broken, 0 orphaned, 0 missing. The milestone hangs off a single shared seam — `std::atomic<int> activeVoiceCount` with a clamped release-store setter (`setActiveVoiceCount`) and acquire-load reads (`getActiveVoiceCount`). No duplicate/shadow count state exists anywhere in the plugin layer.

- Phase 60 defines the atomic + count-aware `allocateVoice` (acquire-load, lazy `% count`).
- Phase 61 fan-out (`applyContinuousVoiceControls`) loops `[0, activeVoiceCount)` each block.
- Phase 62 selector `onChange` drives `setActiveVoiceCount`; default 24 matches the engine default.
- Phase 63 saves `active_voices` into the `[voice]` section and restores it through the *same* clamped setter (seed-24-then-override), with the editor re-syncing the selector via `getActiveVoiceCount()`.

**E2E flows:** selector live-update ✓; `.spu94` save→reload round-trip ✓ (human-verified). **Deferred-by-design:** DAW binary session-state does not carry the count (Phase 63 D-02).
