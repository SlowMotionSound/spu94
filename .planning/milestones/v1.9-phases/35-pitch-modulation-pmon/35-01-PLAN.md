  <action>
    The PMON formula must be applied in spu94_voice_mixer_tick, NOT in spu94_voice_tick.
    Reason: voice_tick has no visibility into other voices' outx. The mixer tick already
    has the voices[] array and processes them sequentially 0..23.

    Refactor the mixer tick voice loop to apply PMON before calling spu94_voice_tick.
    The current voice loop structure is:
      for (v = 0..23): if active, call voice_tick, accumulate sums.

    The new structure needs to:
    1. For each voice v, BEFORE calling voice_tick: if pmon_flags bit v is set AND v > 0,
       compute the PMON-modified pitch and temporarily set it on the voice.
    2. Call voice_tick as before (it uses v->pitch for counter advancement).
    3. outx is already stored by voice_tick at Step 2.75 -- no change needed there.

    Specifically, add PMON logic inside the mixer voice loop, before the voice_tick call:

    If (m->pmon_flags & (1u << v)) AND v > 0:
      int16_t prev_outx = m->voices[v - 1].outx
      uint32_t factor = (uint32_t)((int32_t)prev_outx + 0x8000)
      uint32_t base_step = (uint32_t)m->voices[v].pitch
      int32_t mod_step = (int32_t)((base_step * factor) >> 15)
      if (mod_step > 0x3FFF) mod_step = 0x4000
      if (mod_step < 0) mod_step = 0
      Save original pitch, set v->pitch = (uint16_t)mod_step, call voice_tick, restore original pitch.

    The save/restore pattern ensures the base pitch register is preserved for the next tick.
    The PMON formula computes the effective pitch for THIS tick only.

    Key details from spec:
    - Factor range: 0x0000 (outx=-0x8000) to 0xFFFF (outx=+0x7FFF). Center at 0x8000 (outx=0).
    - Step = (base_pitch * factor) >> 15. This is an unsigned multiply followed by right shift.
    - Clamp: if step > 0x3FFF, step = 0x4000 (NOT 0x3FFF -- PMON can exceed normal pitch max).
    - Voice 0: PMON bit 0 is silently ignored (the if v > 0 guard handles this).

    Also implement the spu94_voice_mixer_set_pmon function body following the
    spu94_voice_mixer_set_eon pattern (validate voice_idx 0..23, set/clear bit in pmon_flags).

    Do NOT modify spu94_voice_tick itself. The PMON pitch override happens entirely in mixer_tick.
  </action>
