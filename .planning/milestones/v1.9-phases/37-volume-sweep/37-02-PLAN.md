<objective>
Implement per-voice volume sweep with independent L/R state machines, all four sweep modes (linear/exponential x increase/decrease), negative-phase sweep, and integrate into the voice tick pipeline.

Purpose: Volume sweep gives each PS1 voice a second independent envelope that ramps vol_l/vol_r automatically, enabling hardware-driven stereo panning, fades, and tremolo without CPU intervention. The sweep uses the shared envelope step helper from Plan 01, guaranteeing bit-identical timing to ADSR.

Output: spu94_sweep.h/.c module, voice_t with sweep fields, voice pipeline integration, sweep unit tests, mixer API for configuring sweep.
</objective>

  <behavior>
    Sweep state struct and API:
    - spu94_sweep_t has: int16_t level, uint32_t counter, uint8_t shift (0..31), uint8_t step (0..3), uint8_t mode (0=linear, 1=exponential), uint8_t direction (0=increase, 1=decrease), uint8_t phase (0=positive, 1=negative), uint8_t active (0/1)
    - spu94_sweep_init: memset + defaults (active=0, level=0)
    - spu94_sweep_tick: if !active return; construct spu94_envelope_state_t from level/counter; call spu94_envelope_step with shift, step, direction, mode, phase; write back level/counter; handle clamping per quadrant
    - spu94_sweep_configure: set mode/direction/phase/shift/step from register bits, set active=1, leave level unchanged (level IS the current volume)

    Clamping boundaries (Pitfall 2 from RESEARCH.md):
    - phase=0 (positive), increase: clamp at +0x7FFF
    - phase=0 (positive), decrease: clamp at 0x0000
    - phase=1 (negative), increase: clamp at -0x7FFF (deeper negative)
    - phase=1 (negative), decrease: clamp at 0x0000 (toward zero)
    - Exception (Pitfall 3): phase bit ignored when direction=decrease AND mode=exponential

    Voice pipeline integration:
    - Add sweep_l and sweep_r (spu94_sweep_t) to spu94_voice_t after adsr field
    - STEP 0 in spu94_voice_tick: if sweep_l.active, tick sweep_l, set vol_l = sweep_l.level; same for sweep_r
    - STEP 3 (volume multiply) is unchanged -- it already uses vol_l/vol_r
    - KON (spu94_voice_key_on): set sweep_l.active=0 and sweep_r.active=0 (SWEEP-07)
    - KOFF (spu94_voice_key_off): no sweep changes (SWEEP-07)

    Mixer API:
    - spu94_voice_mixer_set_sweep_l / set_sweep_r: validate voice_idx 0..23, configure the voice's sweep_l/sweep_r struct, set sweep.level to current vol_l/vol_r, set active=1

    Tests (TDD red phase):
    - test_sweep_init: after init, active=0, level=0, counter=0
    - test_sweep_linear_increase: shift=0, step=0, direction=0, mode=0 -> level increases by (7<<11)=14336 per step trigger
    - test_sweep_linear_decrease: shift=0, step=0, direction=1, mode=0 -> level decreases by (8<<11)=16384 per step trigger
    - test_sweep_exponential_decrease_antistall: level starts at 1, exp decrease -> must reach 0 (anti-stall guard fires)
    - test_sweep_exponential_increase_knee: level above 0x6000, exp increase -> rate drops by 4x
    - test_sweep_independent_lr: configure L=increase, R=decrease on same voice -> L goes up while R goes down
    - test_sweep_kon_deactivates: active sweep, then key_on -> sweep_l.active=0 and sweep_r.active=0
    - test_sweep_koff_no_effect: active sweep, then key_off -> sweep_l.active still 1
    - test_sweep_modifies_vol_directly: after sweep tick, voice.vol_l == sweep_l.level (SWEEP-05)
    - test_sweep_negative_phase_increase: phase=1, direction=increase -> level moves toward -0x7FFF
    - test_sweep_negative_phase_decrease: phase=1, direction=decrease -> level moves toward 0
    - test_sweep_phase_ignored_exp_decrease: phase=1, direction=decrease, mode=exponential -> phase bit has no effect
