# Roadmap: v1.7 DAW Plugin Port

**Drafted:** 2026-05-11
**Target tag:** `v1.7` (TBD at ship)
**Status:** Draft — pre-execution
**Requirements doc:** `.planning/milestones/v1.7-REQUIREMENTS.md` (53 PLUG-* IDs)

## Milestone Goal

Package the bit-faithful SPU-94 engine as a real-time DAW plugin in four formats (VST3, AU, LV2, CLAP) across three operating systems (Linux, macOS, Windows). Eleven user-facing binaries total. Bit-faithful C core untouched; sample-rate conversion and float↔int16 conversion live entirely in the plugin wrapper. Standalone build target retained as an internal dev testbed but is no longer a user deliverable. Beta-distribute via GitHub releases with unsigned binaries; signing only if install friction is reported.

## Phase Sequence

Phases continue numbering from Phase 20 (last v1.6 phase). Six firm phases plus one conditional. Each phase below names its scope, dependencies, and the requirement IDs it satisfies.

### Phase 21: Build Skeleton & CI Matrix

**Goal:** Expand JUCE `FORMATS` from `Standalone` to `Standalone VST3 LV2 CLAP` (+ `AU` on Apple). Integrate `clap-juce-extensions` via CMake `FetchContent` (JUCE 8 lacks native CLAP). Rename `src/standalone/` → `src/plugin/` and move `WavLoader.{cpp,h}` into a new small `src/standalone/` folder. Gate the WAV-loader UI on `wrapperType == wrapperType_Standalone`. Establish a 3-OS GitHub Actions matrix (ubuntu-22.04 / macos-13 or 14 / windows-2022) that builds all 11 user-facing binaries on every push to `main`. Cache submodules + ccache. Smoke test: each binary builds-and-loads in at least one host of its native format.

**Depends on:** none (entry phase)
**Requirements:** PLUG-01..08, PLUG-49..51
**Files (provisional):**
- `CMakeLists.txt`, `src/CMakeLists.txt` — `FORMATS` expansion, FetchContent for `clap-juce-extensions`
- `src/standalone/` → `src/plugin/` rename, all paths updated
- `src/standalone/` (new) — `WavLoader.{cpp,h}` only
- `src/plugin/PluginEditor.cpp` — `wrapperType` gate around WAV-loader UI
- `.github/workflows/build.yml` (new) — 3-OS × 4-format matrix

**Status:** Not started

### Phase 22: Sample-Rate Conversion & Latency Reporting

**Goal:** Integrate `libsamplerate` (BSD-2) as the bidirectional SRC at the `processBlock` boundary. Use `SRC_SINC_MEDIUM_QUALITY` preset. All SRC state and scratch buffers allocated in `prepareToPlay` — zero allocation on the audio thread. Bypass SRC entirely when host SR == 44100. `setLatencySamples()` reports the measured `SRC_in + core + SRC_out` group delay (measured at integration time, not estimated from documentation). Null-test in Reaper at 48 kHz host SR to confirm PDC (Plugin Delay Compensation) alignment. Wrap `processBlock` with `ScopedNoDenormals`.

**Depends on:** Phase 21 (plugin skeleton must exist)
**Requirements:** PLUG-09..16
**Files (provisional):**
- `CMakeLists.txt` — `FetchContent_Declare(libsamplerate ...)`
- `src/plugin/SrcChain.{h,cpp}` (new) — bidirectional SRC wrapper, `prepareToPlay`-allocated
- `src/plugin/PluginProcessor.{h,cpp}` — `prepareToPlay` SRC allocation, `processBlock` chain, `setLatencySamples()` measurement

**Status:** Not started

---

### Phase 23: Float ↔ int16 Boundary

**Goal:** Replace the standalone's direct-int16 audio path with explicit float32 ↔ int16 conversion at the wrapper boundary. Input clamp + truncation (no dither, no noise shaping) — period-faithful per North Star. Saturation matches the C core's `sat_s16` semantics (ADR-0001) — no integer wrap on overflow. Default Input Gain = 0.5 (-6 dB) matching standalone. Existing side-channel limiter (`PluginProcessor.cpp:357-377`) preserved unchanged. Output conversion: int16 → float32 by division by 32768.0f.

**Depends on:** Phase 22 (SRC chain provides the sandwich the conversion sits inside)
**Requirements:** PLUG-17..21
**Files (provisional):**
- `src/plugin/BoundaryConverter.{h,cpp}` (new) — float↔int16 with `sat_s16` semantics
- `src/plugin/PluginProcessor.{h,cpp}` — chain integration, Input Gain default

**Status:** Not started

---

### Phase 24: State Persistence & Host Automation Surface

**Goal:** Wire `getStateInformation` / `setStateInformation` through the existing v1.4 `.spu94` serializer. Wrap the byte payload in a binary container: 4-byte magic `'SPU9'` + 1-byte version + 4-byte body length + body. Locale-independent — no `juce::String::getFloatValue` in the persistence chain (avoids the German/French `1,5` parsing bug). `setStateInformation` applies via the existing `pendingPresetBuf` deferred-apply mechanism (RT-safe). Multi-instance smoke test for independent state. Expose exactly 9 `juce::AudioProcessorParameter`s for host automation (Input Gain, ADPCM Send, Dry Send, Morph Position, Morph Speed, Morph Grit, Dry Level, ADPCM Level, Reverb Level), routed through the existing atomic-scalar + SPSC bridge. Parameter IDs stable across versions.

**Depends on:** Phase 21 (plugin skeleton)
**Requirements:** PLUG-22..31
**Files (provisional):**
- `src/plugin/StateSerializer.{h,cpp}` (new) — binary container wrapper around `.spu94`
- `src/plugin/AutomationParams.{h,cpp}` (new) — 9 `AudioProcessorParameter` definitions + atomic-bridge routing
- `src/plugin/PluginProcessor.{h,cpp}` — `getStateInformation` / `setStateInformation` implementation, parameter registration

**Status:** Not started

---

### Phase 25: Channel Buses & Validator Gates

**Goal:** Declare exactly three bus configurations in `isBusesLayoutSupported`: mono→mono, mono→stereo, stereo→stereo. Mono input duplicated into both reverb L+R inputs (engine always stereo internally). mono→mono sums output L+R back to mono. All other configurations (sidechain, surround, Atmos) rejected. Plugin loads on a mono track in Logic without `auval` failure. Wire `pluginval --strictness-level 7` into CI on every build × every format × every OS. Wire `auval -v aufx <chosen-codes>` on every macOS build. Wire `lv2lint` + `sord_validate` on every LV2 build. Wire VST3 SDK `validator` on every VST3 build. pluginval RT-safety probe must report zero allocations on the audio thread. Any validator warning or error fails CI.

**Depends on:** Phases 22, 23, 24 (validators exercise the full SR + bit-depth + state chain)
**Requirements:** PLUG-32..42
**Files (provisional):**
- `src/plugin/PluginProcessor.cpp` — `isBusesLayoutSupported`, mono-duplication, mono-mix-down
- `.github/workflows/validate.yml` (new or merged into build.yml) — pluginval/auval/lv2lint/vst3-validator gates
- AU plugin codes chosen and recorded in `CMakeLists.txt` `juce_add_plugin(... PLUGIN_CODE ... PLUGIN_MANUFACTURER_CODE ...)`

**Status:** Not started

### Phase 26: Packaging & Beta Distribution

**Goal:** Build per-OS installers: macOS `.pkg` or drag-install `.dmg` placing each format in its standard scan path; Windows Inno Setup installer placing binaries in standard host scan paths; Linux tarball + `install.sh` placing binaries under `~/.vst3`, `~/.lv2`, `~/.clap`. Write the beta README documenting per-host plugin-cache reset procedure (handles stale-cache symptoms in tester feedback loop) and per-OS workaround for unsigned binaries (Gatekeeper / SmartScreen click-through). Plugin window declared fixed-size (matches current standalone GUI). Pick the per-DAW UAT (User Acceptance Testing) matrix here — research assumed Reaper / Ableton Live / Logic / FL Studio; final list selected at this phase. Manual UAT in each chosen DAW: load, save/load state round-trip, multi-instance, automation lane sweep.

**Depends on:** Phase 25 (binaries must pass validators before they go into installers)
**Requirements:** PLUG-43..48 (+ deferred UAT matrix decision resolved here)

- `docs/BETA-README.md` (new) — install + cache-reset + unsigned-binary instructions

## Notes

- The roadmap reflects the architecture lane's finding that v1.7 is materially smaller than the original milestone framing implied — the standalone is already structurally a `juce::AudioProcessor`, so v1.7 is "expand FORMATS + add SRC + add float↔int16 + fill state stubs" rather than a from-scratch plugin build.
- Phase 27 (signing) is intentionally conditional. The default plan is to ship the v1.7 beta unsigned with documented click-through instructions; signing is only triggered reactively if testers report install friction.
- Per-DAW UAT matrix selection is deferred from requirements into Phase 26 (packaging) — picked when we actually need it.
- All file paths are provisional; each phase's plan step refines them.
