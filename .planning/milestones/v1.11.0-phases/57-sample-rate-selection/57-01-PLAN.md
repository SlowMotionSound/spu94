    1. FIX THE TIME MATH during recording: Replace the hardcoded 44100.0 divisor with processorRef.getEncodeRate(). The staging buffer captures at 44100 Hz host rate, but the ADPCM data after SRC will be at encodeRate. So the correct time calculation is:
       - Total ADPCM capacity in samples at encode rate: (SPU94_SPU_RAM_BYTES / 16) * 28 = 917504
       - But the staging buffer is being filled at 44100 Hz. The recordBytesUsed estimates ADPCM bytes from the staging sample count at 44100. After SRC, the actual bytes used will be scaled by (encodeRate/44100).
       - Correct seconds recorded: (recordStagingCount-equivalent * (1.0/44100.0)) -- this is wall-clock time, use the host rate here.
       - Correct time remaining: compute total seconds available = 917504.0 / encodeRate, then subtract seconds recorded.
       So: secondsRecorded = samplesRecordedAt44100 / 44100.0 (wall-clock, correct). totalSeconds = 917504.0 / encodeRate. remainSeconds = totalSeconds - secondsRecorded.
