**test_process_adpcm.c** -- Create a Unity test file covering all 6 ADPCM-INT requirements. Follow the same setUp/tearDown pattern as test_process_basic.c (allocate state_buf and work_buf on the stack or via aligned arrays, call spu94_init, tearDown calls spu94_destroy). Include `spu94_state_internal.h` for direct struct field inspection (same pattern as test_process_mix_bus.c). Include `spu94_adpcm.h` for SPU94_ADPCM_BLOCK_SAMPLES constant.

Tests to implement:

**1. test_adpcm_off_by_default (ADPCM-INT-05)**
- After spu94_init, assert `spu94_get_adpcm_enabled(state) == 0`
- Assert `spu94_get_total_latency_samples(state) == 58`

**2. test_adpcm_toggle_set_get (ADPCM-INT-01)**
- Call `spu94_set_adpcm_enabled(state, 1)`, assert `spu94_get_adpcm_enabled(state) == 1`
- Call `spu94_set_adpcm_enabled(state, 0)`, assert `spu94_get_adpcm_enabled(state) == 0`
- Call `spu94_set_adpcm_enabled(state, 42)`, assert `spu94_get_adpcm_enabled(state) == 1` (normalization to 0/1)

**3. test_adpcm_null_safety (ADPCM-INT-01)**
- `spu94_set_adpcm_enabled(NULL, 1)` -- no crash
- `spu94_get_adpcm_enabled(NULL) == 0`
- `spu94_get_total_latency_samples(NULL) == 58`

**4. test_adpcm_disabled_matches_baseline (ADPCM-INT-05)**
- Create two fresh states (state_a, state_b). Leave ADPCM disabled on both.
- Feed identical 128-sample impulse (sample 0 = 16000, rest = 0) through spu94_process on both.
- Assert output arrays are bit-identical.
- Then enable ADPCM on state_b, disable it, feed same input on fresh states again.
- Assert output still matches baseline (disable restores original behavior).

**5. test_adpcm_enabled_differs_from_disabled (ADPCM-INT-01)**
- Create two fresh states. Enable ADPCM on one.
- Feed identical 128-sample impulse through both.
- Assert outputs are NOT identical (ADPCM coloration must alter the signal).
- The ADPCM-enabled output should have the first 28 samples as silence (latency) followed by ADPCM-colored audio.

**6. test_adpcm_latency_28_samples (ADPCM-INT-02)**
- Enable ADPCM. Feed 56 samples of constant value 10000 (2 full ADPCM blocks).
- The first 28 output samples from spu94_process (before FIR chain) should be zeros (the initial output buffer is zero-filled).
- To verify: compare ADPCM-enabled output vs ADPCM-disabled output. The ADPCM-enabled output should be delayed by 28 samples relative to disabled.
- Concrete check: with ADPCM disabled, feed a single-sample impulse and record peak position. With ADPCM enabled, feed same impulse and record peak position. The enabled peak should be 28 samples later. Use the `spu94_fir_chain_step_reverb_bypass` path if available, or use Off preset (zero-gain reverb) so the FIR pass-through is clean. Actually, use Off preset so output = FIR-processed input only. Feed 256 samples with impulse at sample 0. Find the sample with max absolute value in each output. Assert `peak_enabled - peak_disabled == 28`.

**7. test_adpcm_latency_report (ADPCM-INT-03)**
- Disabled: `spu94_get_total_latency_samples(state) == 58`
- Enable: `spu94_get_total_latency_samples(state) == 86`
- Disable: `spu94_get_total_latency_samples(state) == 58`
- Also verify `spu94_get_latency_samples() == 58` always (backward compat)

**8. test_adpcm_state_zeroed_by_init (ADPCM-INT-04)**
- After spu94_init, directly inspect struct fields:
  - `state->adpcm_enabled == 0`
  - `state->adpcm_buf_pos == 0`
  - `state->adpcm_state_l.old == 0 && state->adpcm_state_l.older == 0`
  - `state->adpcm_state_r.old == 0 && state->adpcm_state_r.older == 0`
  - All 28 entries of adpcm_out_buf_l are 0

**9. test_adpcm_state_zeroed_by_reset (ADPCM-INT-04)**
- Enable ADPCM, feed 100 samples of noise (alternating +10000/-10000).
- Call spu94_reset(state). Then re-init with spu94_init (reset zeros the struct but caller must re-init).
- Actually, check the reset behavior: spu94_reset zeros the entire struct via spu94_zero_bytes. After reset, adpcm_enabled should be 0, buf_pos should be 0, codec states should be zero. Verify by direct struct inspection after reset.
- NOTE: spu94_reset preserves work_buf pointer then re-zeros. After reset, call spu94_get_adpcm_enabled -- should return 0.

**10. test_adpcm_midstream_toggle_discards_partial (ADPCM-INT-04)**
- Enable ADPCM. Feed 14 samples (half a block -- buf_pos should be 14).
- Verify `state->adpcm_buf_pos == 14` via direct struct inspection.
- Disable ADPCM via spu94_set_adpcm_enabled(state, 0).
- Verify `state->adpcm_buf_pos == 0` (partial buffer discarded).
- Verify `state->adpcm_out_buf_l[0] == 0` (output buffer zeroed on disable).

**11. test_adpcm_state_size_under_cap (ADPCM-INT-05)**
- `TEST_ASSERT_TRUE(spu94_state_size() <= SPU94_STATE_SIZE_MAX)`
- This is also enforced at compile time by _Static_assert, but a runtime test makes it visible in ctest output.
