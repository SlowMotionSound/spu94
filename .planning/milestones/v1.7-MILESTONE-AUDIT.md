## Cross-Phase Integration Issues

### 1. State Restore Race Condition (PLUG-23, PLUG-26, PLUG-27)

In `PluginProcessor.cpp`, the `filePresetReady` block in `processBlock` calls `setValueNotifyingHost` (which acquires a lock — not RT-safe) and may overwrite correct param values that `setStateInformation` just wrote, because the flag can be observed by the audio thread before the message thread finishes writing all param values.

**Practical impact:** Low — requires precise timing to trigger. The preset load completes in < 1ms on the message thread, and the audio thread only checks the flag once per block (every ~5ms at 48kHz/256 buffer). But it's a real deviation from the Phase 24 plan which specified `setValue` (audio-thread-safe) instead of `setValueNotifyingHost`.

### 2. Plugin Unit Tests Not Run in CI

`tests/plugin/` contains 5 test programs that compile during the plugins.yml build but are never invoked (`ctest` is not called). Regressions in state serialization, bus layout, and null passthrough would go undetected.
