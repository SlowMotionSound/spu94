**1. Constructor changes:**

Add the Advanced toggle setup (after the macro/register panel setup):
```cpp
addAndMakeVisible(advancedToggle);
advancedToggle.setColour(juce::TextButton::buttonColourId, juce::Colour(0xFF5A5A5A));
advancedToggle.setColour(juce::TextButton::textColourOffId, juce::Colour(0xFFB0B0B0));
advancedToggle.onClick = [this] {
    bool showAdvanced = !registerViewport.isVisible();
    macroPanel.setVisible(!showAdvanced);
    registerViewport.setVisible(showAdvanced);
    advancedToggle.setButtonText(showAdvanced ? "Macro" : "Advanced");

    if (!showAdvanced) {
        // Switching from Advanced to Macro: request re-derive (MACRO-04, Pitfall 1)
        processorRef.getRequestDeriveAll().store(true, std::memory_order_relaxed);
    } else {
        // Switching to Advanced: sync raw sliders from current state (Pitfall 2)
        registerPanel.updateFromShadows();
    }
};
```

Also trigger derive-all on startup to initialize macro knob positions from the loaded preset:
```cpp
processorRef.getRequestDeriveAll().store(true, std::memory_order_relaxed);
```

**4. Timer callback extension:**
In timerCallback(), AFTER the existing tempo sync polling section and before the end, add a new section for macro panel sync:

```cpp
// ===== MACRO PANEL SYNC =====
if (macroPanel.isVisible()) {
    macroPanel.updateKnobPositions();
    macroPanel.updateUnitLabels();
    macroPanel.updateSnapDropdowns();
}
```

This runs at the existing 30Hz timer rate. The macro panel methods handle all the detail (reading atomics, converting units, polling dropdowns).

**5. Preset load sync:**
In the existing preset load path within timerCallback (where factory presets and file presets are detected and GUI state is synced), the derive-all is already triggered by processBlock (Plan 01 adds requestDeriveAll.store(true) in the preset drain path). The timer will pick up the derived positions on the next cycle. No additional code needed in the editor for preset load macro sync.

However, the existing `captureBaseline()` call after preset load should also capture the macro knob states as part of the modified-state baseline. If the existing baseline struct only tracks register values + mixer settings, extend it to also include the macro knob positions so that modified-state detection works correctly after preset load. Add to the Baseline struct:
```cpp
float macroRoomSize, macroBuffer, macroDecay, macroReflectivity;

```
And update captureBaseline() and checkModified() accordingly. ALTERNATIVELY: if this is too much work for the modified-state tracking, skip it -- the existing register-level modified detection still works because macro knob changes write to registers, which change shadows, which trigger modified detection.

**6. Ensure existing per-register tempo dropdowns still work:**
The existing per-register tempo dropdowns in the toolbar area (perRegDropdowns[10]) remain functional. They're independent of the macro panel's echo snap dropdowns. Both write to the same underlying C core state through different paths (the toolbar dropdowns use the v1.5 spu94_set_subdivision API directly, while the macro panel snap dropdowns use the snap module). When the macro panel is visible, the toolbar's per-register dropdowns could be visually confusing since they duplicate functionality. Consider hiding the perRegDropdowns when the macro panel is visible, but this is OPTIONAL -- the existing behavior is not broken.
