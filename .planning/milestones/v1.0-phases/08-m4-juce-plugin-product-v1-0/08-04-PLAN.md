Modify the `processBlock` output section. Currently (from Plan 02) it writes SPU output directly to the JUCE buffer. Replace that section with the equal-power crossfade per RESEARCH.md Pattern 8:

After the `spu94_process(spu, tmpL_in, tmpR_in, tmpL_out, tmpR_out, n)` call, replace the output loop with:

```cpp
// Equal-power crossfade: dry input vs SPU wet output (D-02, STANDALONE-06)
const float wet = wetDry.load(std::memory_order_relaxed);
const float wetGain = std::sqrt(wet);
const float dryGain = std::sqrt(1.0f - wet);

auto* outL = buffer.getWritePointer(0);
auto* outR = (buffer.getNumChannels() > 1) ? buffer.getWritePointer(1) : nullptr;

for (int i = 0; i < n; ++i) {
    const float dryL = tmpL_in[i] / 32768.0f;
    const float dryR = tmpR_in[i] / 32768.0f;
    const float spuL = tmpL_out[i] / 32768.0f;
    const float spuR = tmpR_out[i] / 32768.0f;

    outL[i] = dryL * dryGain + spuL * wetGain;
    if (outR) outR[i] = dryR * dryGain + spuR * wetGain;
}
```

This preserves perceived loudness across the sweep (sqrt pan law):
- wet=0.0: dryGain=1.0, wetGain=0.0 -- user hears dry input only
- wet=1.0: dryGain=0.0, wetGain=1.0 -- user hears SPU output only
- wet=0.5: dryGain=0.707, wetGain=0.707 -- constant-power midpoint

No allocations added -- `std::sqrt` is a pure math operation, and the float division is already present from Plan 02.
