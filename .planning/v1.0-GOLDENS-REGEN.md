# Golden-File Regeneration — 2026-04-24

**Trigger:** ADR-Phase-6-I (reverb input wiring correction).
**Scope:** All 50 WAV goldens + 50 SHA-256 sidecars under `tests/golden/`.
**Tool:** `scripts/regenerate_goldens.py`.
**Verified:** `python3 scripts/regenerate_goldens.py --check` → `PASS: 50/50 goldens match`.

## Why regenerate

Before ADR-Phase-6-I, `spu94_process` wrote the raw 44.1 kHz input sample into `state->mix_bus_l/r`, and `spu94_reverb_body` read that raw sample as the reverb's input on every 22.05 kHz tick — bypassing the Phase 4 anti-alias half-band FIR for the reverb-input path. HF content above 11.025 kHz aliased into the reverb network.

After ADR-Phase-6-I, `chain_step_impl` writes `state->mix_bus_l = dec_l; state->mix_bus_r = dec_r;` on the retained phase, feeding the decimator's band-limited 22.05 kHz output into the reverb. HF input content is now properly attenuated before hitting the reverb, per Phase 4's stated goal.

Every 44.1 kHz sample rendered by the CLI was affected. All 50 golden SHA-256s changed.

## What was regenerated

50 WAV files and 50 SHA-256 sidecars, covering:

- 10 presets: Off, Room, Studio A, Studio B, Studio C, Hall, Half Echo, Space Echo, Echo, Delay.
- 5 inputs per preset: impulse, sine_1khz, sweep, white_noise, silence.
- Total: 10 × 5 = 50 (preset, input) pairs.

## What did NOT change

- `tests/benchmarks/benchmark_baselines.json` — timing harness, unrelated to DSP bit content.
- Any unit test expected values — unit tests assert invariants (non-silence, stability, truncation direction, boundary behavior), not specific sample bits.
- Public API surface — `spu94_process`, `spu94_load_preset`, etc. are unchanged in signature and semantics.

## What the regeneration confirmed

- 50/50 `--check` runs pass post-regen (bit-identical between committed sidecars and fresh renders).
- 105/105 modulation harness entries report `stability_ok: true` (all 35 registers × 3 modulation modes).
- 72 out of 73 ctest targets pass; the 73rd (`regenerate_goldens_meta`) was the one failing due to the pre-regen SHA mismatch, and passes after the regen committed here.
